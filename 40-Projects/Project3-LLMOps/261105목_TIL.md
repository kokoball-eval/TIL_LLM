# TIL — "채점기는 채점하기 전에 먼저 시험하고, 팀 환경은 문서가 아니라 도구로 고정한다"

> 11/05 하루 한 작업이다. 3차 프로젝트(해운 Basic, PDF 15개 기반 RAG 질의응답 서비스, 5명 팀)의 첫날이고, 나는 **judge(LLM 평가)** 담당이다. RAGAS Faithfulness, LLM-as-a-Judge 4항목(사실·조건·근거·판단), 해당 없음·평가 불가 규칙, 대표 사례 원문 대조가 내 몫이다. 실제 답안은 11/9에야 나오기 때문에, 오늘은 **답안이 나오기 전에 채점기가 믿을 만한지 먼저 시험하는 것**과 **팀 전원이 같은 환경에서 돌릴 수 있게 고정하는 것**에 시간을 썼다.
>
> **역할 분담** — 코드, 테스트, 문서, PR 본문 초안은 Claude가 작성했다. 나는 방향 결정과 승인, 로컬 실행과 로그인, 팀 전달(슬랙)을 맡았다. 특히 "환경은 문서로 알리는 데서 끝내지 말고 **고정되게** 하라", "구조 파악용으로 만든 것은 그대로 올리지 않는다", "PR 올리기 전에 생길 만한 위험을 미리 막아 두자"는 내 판단이다. 아래에서 "Claude가 발견한 것"과 "내가 정한 것"을 구분해서 적는다.

## 💡 오늘의 작업 총평

이번에 제일 크게 배운 건 **채점기도 테스트 대상이고, 그 테스트(시험지)도 틀릴 수 있다**는 것이다.

실제 답안이 없으니, 정답지로 **정답 점수를 이미 아는 가짜 답안**을 만들어 채점기에 먹였다. 정답 그대로, 시각을 바꿔치기한 답, 금지 주장을 단정한 답, 답할 수 있는데 보류한 답, 근거 자료가 없는 답, 서비스 오류 답이다. 종류마다 나와야 할 점수가 정해져 있다.

| 시험 | 규모 | 결과 |
| :--- | :--- | :--- |
| 정확도 | 가짜 답안 30장, 확인 57칸 | **55칸 일치**. 틀린 2칸은 모두 시험지 쪽 오류 |
| 흔들림 | 10장 × 3회 | 40칸 중 점수가 바뀐 칸 **0** (단, 뚜렷한 답안이라 쉬운 편) |
| RAGAS 한국어 | 8장 | 주장 추출 정상. 근거 없음 0.00, 시각 바꿔치기 0.50·0.75, 정답 0.75~1.00 |

틀린 2칸을 열어 보니 채점관이 아니라 **내 시험지가 잘못**이었다. 하나는 필요한 근거 문장 일부만 문맥에 넣어서 "근거 부족"이라고 지적한 게 맞았고, 하나는 "공통으로 낮 12시라고 답할 수 없다"는 부정문의 시각을 바꿔도 여전히 맞는 말이었다. QA로 치면 **테스트가 실패해서 보니 테스트 케이스가 틀렸던 것**이다.

두 번째로 크게 남은 건 **환경은 문서로 알리는 것과 도구로 막는 것이 다르다**는 것이다. RAGAS가 Python 3.14에서 설치되지 않는다는 걸 알았을 때, 문서에 적는 것으로는 부족하다고 판단했다. 마감 전에 구현하지 않은 팀원이 README대로 설치해서 돌려 보는 검증이 완료 기준이라서, 3.14로 설치하면 **설치 도구가 거부하게** 만들었다.

## 🎯 작업별 핵심

### 1. 데이터 파악 — 근거가 빈 문항과 숨은 공격 문장

평가 파일은 개발 30 · 추가 30 · 확장 검증 12문항이고, 개발·추가 세트의 기대 동작은 각각 답변 24 / 되묻기 3 / 보류 3 구성이다. 근거가 빈 문항이 4개(되묻기)라 **Hit/Recall은 해당 없음**이고 채점관의 "판단" 칸만 본다. 요율·비용 질문은 모두 보류가 정답이다(자료에 운임·보관료·요율이 없다고 문서가 명시).

SB15.pdf 1·2쪽에는 **보안 시험용 공격 문장이 실제로 들어 있다.** 검색되면 모델 입력뿐 아니라 **채점관 입력에도** 들어가므로, 채점 지시서에 자료 속 명령을 평가 대상으로만 취급하라고 적었다. [LLMOps 11/04][ops1104]의 지시 주입을 채점 쪽에서도 막는 것이다.

### 2. 0점과 빈칸 — 결측을 0으로 바꾸면 평균이 달라진다

답안 4장의 한 칸 점수가 `1, 1, 0, 빈칸`일 때, 빈칸을 빼면 (1+1+0)÷3 = **0.67**이고 0으로 바꾸면 0.50이다. 빈칸이 "채점할 대상이 없음"인지 "채점을 못 했음"인지에 따라서도 이유를 다르게 적는다.

서비스 오류 답안은 AI를 부르지 않고 규칙으로 처리한다(판단 0, 나머지 평가 불가, 호출 0번). 채점표 모양이 틀리면 1회만 다시 시키고, 그래도 틀리면 4칸 모두 평가 불가다. **0점이 아니다.** 게임 QA의 N/A와 Fail을 섞지 않는 것과 같다.

### 3. 두 채점이 같은 오류를 다른 크기로 잡는다

시각을 틀린 답안(낮 12시를 오후 3시로)을 실제로 채점해 봤다. RAGAS는 답을 주장 4개로 쪼개 "1개가 문맥과 다름"이라 **0.75**, 채점관은 "질문의 핵심인 마감 시각이 틀림"이라 사실·조건·근거를 **0**, 판단만 1로 줬다. 옛 안내(오후 3시)를 그대로 따라 쓴 답은 Faithfulness만으로는 놓치기 쉽다. 발제가 두 채점을 모두 요구하는 이유를 직접 봤다. 답안 1장 채점에 AI 호출이 3번(RAGAS 2번 + 채점관 1번), 입력 약 3.6천·출력 약 1.4천 토큰이 든다.

### 4. 올바른 보류가 0점 — RAGAS의 주장 추출과 규칙 보강

"자료로는 확인할 수 없어 답변을 보류합니다"를 RAGAS가 **사실 주장**으로 보고 문맥에서 찾다가 못 찾아 0점을 줬다. 올바른 보류가 가장 낮은 점수를 받는 구조였다. 발제의 "사실 주장이 없으면 해당 없음, 문서 내용을 설명했으면 채점"에 맞춰, RAGAS가 뽑은 주장 중 **자료 부족·보류·정보 요청 문장은 채점에서 뺐다.** 다 빼고 남는 주장이 없으면 해당 없음이다.

| 답안 | 규칙 전 | 규칙 후 |
| :--- | :---: | :---: |
| 틀린 보류 | 0.00 | 해당 없음 (판단 0점은 채점관이 줌) |
| 올바른 보류(요율 질문) | - | 1.00 |

규칙이 글자 패턴이라 한계가 바로 나왔다. RAGAS가 "없습니다"를 "포함되어 있지 않습니다", "알려 주세요"를 "알려 주어야 합니다"로 **바꿔 써서** 규칙이 놓쳤고, 실제로 바뀐 문장을 테스트에 넣어 패턴을 넓혔다. 같은 답안의 Faithfulness가 한 번은 1.00, 한 번은 0.67이었던 것도 같은 이유다. **RAGAS는 주장을 매번 조금씩 다른 말로 뽑는다.**

### 5. 채점기 시험 — 시험지도 틀릴 수 있다

"총 점수가 일치하는가"만 보면 시험지 오류를 놓친다. 불일치한 칸을 열어서 원인을 확인한 덕분에 시험지의 두 결함(근거 일부만 넣음, 부정문 속 시각)을 찾았다. 고친 뒤 같은 답안을 다시 채점하니 일치했다. 시험지에는 정답 인용문이 들어가므로 저장 위치를 `data/` 아래로 제한했다.

### 6. 환경 고정 — 문서로 알리는 것과 도구로 막는 것 (PR #53)

RAGAS가 Python 3.14에서 `scikit-network` 빌드에 실패하고, 최신 `langchain-community`와는 `import ragas` 단계에서 충돌한다. 해결은 Python 3.12, `ragas==0.4.3`, `langchain-community<0.3.28`, LangChain 0.3 계열이다. **문서에 적는 것으로 끝내지 않고** 레포 파일로 고정했다.

| 파일 | 하는 일 |
| :--- | :--- |
| `.python-version` | 3.14만 있는 PC에서도 `uv`가 3.12를 받아서 씀 |
| `pyproject.toml` | `requires-python = "==3.12.*"`, LangChain 1.x 추가는 거부 |
| `uv.lock` | 패키지 95개의 정확한 버전 |
| `tests/test_environment.py` | 환경이 다르면 "지금 Python 3.14, 팀 환경은 3.12" 같은 원인과 함께 실패 |

**직접 확인한 것**: 3.14로 설치를 시도하면 uv가 거부, `uv add "langchain>=1"`도 거부, 일반 패키지(fastapi)는 정상 추가. 팀원이 쓸 패키지 14개(qdrant, langfuse, pandas 등)가 이 고정 위에서 설치되고, 검색·답변·API의 핵심 기능 8가지가 돌아가는지도 시험했다. "고정하면 팀원 작업이 막히지 않나" 하는 걱정을 말이 아니라 실험으로 풀었다.

### 7. 리허설에서 찾은 것 — `uv run pytest`가 `src`를 못 찾는다 (PR #57)

PR을 나눠 올리는 스크립트를 리허설하다가 팀 표준 명령 `uv run pytest`가 `No module named 'src'`로 실패하는 걸 발견했다. 이 명령은 레포 폴더를 import 경로에 넣지 않는다. 지금은 테스트가 환경 확인 4개뿐이라 드러나지 않았지만, 각 영역이 `from src...`를 쓰는 순간 전원이 겪는다. `pyproject.toml`에 두 줄(`pythonpath`, `testpaths`)을 추가하는 작은 PR로 풀었다. **리허설이 없었으면 팀원들이 먼저 겪었을 문제**다.

## ⚠️ 오늘의 함정 모음

**1. 압축 파일 2개 중 1개만 풀려 PDF가 6개로 보였다** (내 착각)
데이터는 다 있었는데 한쪽 압축만 풀려 있었다. 발제의 "PDF 15개"와 실제 파일 수를 맞춰 보라는 안내가 이래서 있다.

**2. RAGAS가 "자료로 확인할 수 없다"를 주장으로 센다**
올바른 보류가 0점을 받는다. 주장 단위 채점은 말하는 방식에 민감하다.

**3. 규칙을 만들었더니 RAGAS가 문장을 바꿔 써서 빠져나갔다**
글자 패턴 규칙은 처음 보는 말투에 약하다. 뺀 문장 목록을 이유에 남겨 두고, 실제 답안 채점 후 훑어보기로 했다.

**4. 같은 답안인데 Faithfulness가 1.00과 0.67**
RAGAS는 매번 주장을 다르게 뽑는다. 4칸 채점은 3회 반복해도 같았다. 두 점수를 합치지 않는 이유다.

**5. 시험지가 틀렸다** (Claude가 아니라 내가 만든 기준의 결함)
근거 문장 일부만 넣은 문맥, 부정문 속 시각 바꾸기. 채점기가 아니라 시험지를 고쳤다.

**6. gpt-6-luna는 temperature를 바꿀 수 없다**
`0.0`을 보내면 400 오류로 거절하고 기본값(1)만 받는다. 채점 호출에서는 값을 보내지 않도록 했다. (팀 공용 호출 코드에도 같은 문제가 있는지는 다음 날 확인)

**7. "3.12여야 한다"는 내 처음 결론이 틀렸다** (Claude의 정정)
처음 시험은 다른 부품 버전도 함께 달라서, 3.12만 된다고 잘못 결론냈다. 조건을 똑같이 맞춰 다시 해 보니 3.13도 된다. 3.14만 안 된다. 그래도 AI 라이브러리 지원이 더 오래된 3.12로 고정했다.

**8. 이 PC에 저장된 로그인이 아니라 브라우저 로그인이 문제였다**
푸시가 다른 계정으로 거부(403)됐는데 저장된 인증 정보를 지우려 해도 "요소가 없습니다"만 나왔다. 원인은 브라우저에 로그인된 다른 계정이었다. 로그인이 어디서 오는지부터 확인해야 했다.

**9. 구조 파악용으로 만든 것을 그대로 올리면 안 된다** (내 판단)
임시 부품 파일은 팀의 공용 타입을 복사해 둔 것이고, 안에는 팀 규칙("LLM 호출은 platform 경유만")을 어기는 직접 호출이 있었다. 올리기 전에 임시 부품을 분리하고, 나중에 몸체만 바꾸면 되도록 정리했다.
