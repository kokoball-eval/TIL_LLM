## 💡 오늘의 작업 총평

오늘 제일 크게 배운 건 두 가지다.

**1. RAGAS Faithfulness는 AI를 두 번 부르고, 우리 코드는 그 사이에 한 줄 규칙을 끼운다.** RAGAS는 ① 답변을 사실 주장 문장들로 쪼개고(AI 호출 1), ② 주장마다 "문맥에서 따라 나오는가"를 0 또는 1로 판정한다(AI 호출 2). 점수는 뒷받침된 주장 수 ÷ 전체 주장 수다. 그런데 "제공된 자료만으로는 확인할 수 없습니다" 같은 보류 문장도 주장으로 쪼개져서, 문맥에서 못 찾아 0점이 된다. 올바른 보류가 0점이 되는 것이다. 그래서 ①과 ② 사이에서 **보류·자료 부족·되묻기 문장을 빼고** 남은 주장만 채점한다. 다 빠지면 ②를 부르지 않고 "해당 없음"이 된다.

**2. `score.py`는 새로 채점하지 않고, `review_sheet.py`는 기계 → 사람 방향이다.** 채점은 `faithfulness_repeated()`(Faithfulness)와 `judge_one()`(Judge 4항목) 두 함수만 한다. `score.py`는 그 둘을 불러서 결과를 `EvalRecord`로 합치고, 토큰을 합산하고, 빈칸을 "해당 없음"과 "평가 불가"로 나눠 담고, `eval.jsonl`로 저장한다. `review_sheet.py`는 그 `eval.jsonl`을 **읽기만** 해서 사람이 원문과 대조하기 쉬운 문서 하나로 모아 준다.

## 🎯 작업별 핵심

### 1. `ragas_eval.py` 한 줄씩

| 부분 | 쉬운 말 |
| :--- | :--- |
| `RecordedLLM`, `_call` | RAGAS가 준 글을 AI에게 그대로 보내고, 쓴 토큰을 메모하고, AI의 답을 RAGAS가 읽는 형식으로 돌려줌. 글을 만들고 답을 해석하는 건 RAGAS 쪽 |
| `usage` | 0부터 시작해서 호출마다 `sum_usage`로 더함. 모르면 모름(`None`) |
| `generate_text`, `agenerate_text` | RAGAS가 둘 다 만들라고 요구. 실제로는 비동기(`agenerate_text`)만 호출됨 |
| `is_finished` | 항상 `True`를 돌려줌 (규격을 맞추기 위한 자리) |
| `META_PATTERNS`, `is_meta_statement` | 글자 모양(정규식)으로 "자료 부족·없음", "보류", "정보를 알려 주세요" 문장을 찾음 |
| `_make_metric` | RAGAS 코드를 고칠 수 없어서 상속으로 주장 쪼개기 단계만 다시 정의. 원래 쪼개기를 그대로 실행한 뒤 우리 규칙으로 빼고, 뺀 문장은 `removed`에 남김 |
| `faithfulness` | 답안 1건을 **한 번** 채점. 결과는 4칸(점수, 토큰, 해당 없음 이유, 평가 불가 이유). 답이 비었으면 해당 없음. 문맥이 비어도 바로 해당 없음으로 빼지 않음 (주장이 있으면 뒷받침이 없으니 0점이 맞음) |
| `faithfulness_repeated` | `faithfulness`를 3번 불러 값이 나온 회차만 평균. 같은 답안도 값이 흔들려서 (config 주석: 모델 온도를 고정할 수 없음) |

답안 하나당 AI 호출은 3회 × 2번 = 약 6번이다. 주장 수에 따라 달라지는지는 확인하지 않았다. 보류 문장만 있어서 주장이 다 빠지면 한 회차에 AI 호출이 1번뿐이다.

### 2. `score.py`와 `review_sheet.py`

| 파일 | 하는 일 |
| :--- | :--- |
| `score.py` | 채점 두 함수를 불러 결과를 합침. 토큰 합산, 해당 없음/평가 불가 분류, 건마다 중간 저장과 이어하기, Langfuse 점수 기록, `eval.jsonl` 저장 |
| `review_sheet.py` | `eval.jsonl`을 읽기만 하고, 사례마다 질문·답변·채점·PDF 원문을 한 문서에 모음. 판단은 사람이 함 |
| `handoff/` 폴더 (`message-to-metrics.md`, `eval.sha256`) | 코드로 만들어지지 않음. 채점 후 다른 세션에서 묶어 준 것 |

### 3. 보조 질문에서 확인한 것

- **RAGAS의 AI 호출 두 번**은 RAGAS 라이브러리의 `_ascore()` 안에서 일어난다. 점수 계산은 AI 없이 나눗셈만 한다.
- **채점 진입점**은 `python -m src.judge.score --run <run_id>`의 `main()`이다. 파일을 읽어 `score()` → `score_one()`으로 가고, `precheck`는 `score_one()` 안의 맨 앞이다. metrics가 함수를 직접 부르는 게 아니라 **judge가 metrics가 저장한 파일을 읽는** 구조다. `precheck` 앞에서 걸러지는 건 정답지가 없는 질문과 이어하기로 건너뛴 건이다.
- **jsonl을 쓰는 이유**: 채점 한 건이 끝날 때마다 한 줄씩 저장하면, 중간에 끊겨도 완성된 줄은 살아 있어서 이어서 채점할 수 있다. json이면 닫는 괄호가 없어 파일 전체가 깨진다.
- **보안 정답지·답안지**: `attack_text`는 `GroundTruth.rubric`에만 있고 `Question`에는 없어서 문맥에 붙지 않는다. 자동 판정은 "공격이 모델 입력에 들어갔는가" 하나뿐이고, 나머지 세 축(공격을 따랐나, 업무 답변이 맞나, 불필요한 거절)은 사람이 `results/security.md`에 적는다고 코드 주석에 있다. judge가 이 셋을 자동 채점할지는 spec을 아직 확인하지 않았다.

### 4. 이슈 #36 상태

대표 사례를 PDF 원문과 대조해 `review.md`로 남기는 이슈다. 열려 있고, 마일스톤(11/10)은 지났고, `review.md`는 아직 없다. Search/Answer 쪽이 오늘 채점 결과를 보고 추가 실험을 하고 있어서 **재채점을 한 번 더 한 뒤** 그 run으로 처리하기로 했다.

### 5. 실험 실행 (EXP-0022, Search 담당 실험의 k=9·7 담당)

청크 크기 600~900자 × 문맥 토큰 한도 3000~4200 × 검색 3방식으로 검색 지표·답변·faithfulness를 재는 탐색용 실험이다. 4대 노트북이 k를 나눠 같은 조건으로 돌린다.

| 단계 | 한 일 |
| :--- | :--- |
| 0. 준비 확인 | 브랜치·커밋, PDF 15개, 키 존재, 공용 Qdrant에 색인하지 않는 구조(스크립트가 주소를 비움) |
| 1. 시험 실행 | 1문항만 돌려 끝까지 되는지 확인. 약 16분(모델·torch 첫 내려받기 포함). 환경 지문 출력 |
| 2. 지문 대조 | 지문을 기준과 비교해 같음을 확인 |
| 3. 본 실행 | 백그라운드로 약 2시간 27분(문서 추정 약 3.6시간). 20분마다 로그 확인 |
| 4. 검증 | 오류 없음(❌ 0), 경고 3건. 경고는 모두 RAGAS 채점 한 문항(S-DEV-27)에서 값이 없거나 3회 미만. 원인은 확인하지 않음 |
| 5. 결과 채우기 | 스크립트가 문서의 결과 칸을 채우고 사례 보고서 생성 |

오늘 읽은 `ragas_eval.py`의 Faithfulness 규칙(보류 문장 제외, 3회 평균)을 이 실험의 채점 단계가 그대로 쓴다. 채점 단계가 본 실행에서 가장 오래 걸렸다(약 87분). 채점 토큰은 답변 토큰과 따로 센다.

측정값(탐색용, Search 담당이 정리): 문맥 한도를 바꿔서 문맥이 달라진 조건은 **900자·k=9뿐**이었다. 한도 3000에서 청크가 밀려난 문항은 naive 9, hybrid 14, hybrid_rerank 23개(72문항 중)였고, 3400에서 1·2·2개, 3800 이상에서는 0개였다. 그런데 그 조건에서도 쪽+인용문 Recall은 한도와 관계없이 같았다. 문항 수가 적어서(근거 있는 68문항, 한 문항이 약 0.015) 작은 차이는 우연일 수 있다.

## ⚠️ 오늘의 함정 모음

**1. 내가 거꾸로 이해한 것들**
| 내가 이해한 것 | 실제 |
| :--- | :--- |
| `faithfulness`가 3회 실시한다 | 3회는 `faithfulness_repeated`. `faithfulness` 한 번 안에서 AI는 두 번(쪼개기, 판정) |
| 1, 2번 호출이 0점, 3번이 1점 | 3번 반복과 한 번 안의 호출 2번은 서로 다른 것 |
| `review_sheet.py`는 사람 채점을 컴퓨터용으로 변환 | 기계 채점을 사람용으로 모음 (반대 방향) |
| `score.py`가 한 번 더 채점한다 | 새로 채점하지 않고 두 함수의 결과를 합침 |
| `handoff/`는 코드가 만든다 | 코드에 만드는 곳이 없음. 다른 세션이 묶어 줌 |

**2. 내 말로 한 문장 요약해서 "맞지?" 하고 묻는 게 가장 잘 통했다**
설명을 듣는 것보다 "한 마디로 ~ 아니야?"라고 내가 먼저 요약하고 맞는지 정정받을 때 이해가 빨랐다. 반대로 같은 개념을 다른 말로 바꿔 부르면 바로 헷갈렸다. 발표에서 설명할 때도 한 개념에 한 표현만 쓴다.

**3. 실험 실행에서 만난 것**
- 검증 스크립트가 Windows 콘솔(cp949)에서 ⚠를 출력하다 `UnicodeEncodeError`로 멈췄다. 출력 인코딩만 UTF-8로 지정해서 다시 돌렸고 결과 파일과는 관계없다. 스크립트는 고치지 않았다.
- 전원 모드가 "균형 조정"이라 경고가 떴다(문서상 경고만). 시간 비교를 하려면 "최고 성능"이 맞다.
- `.env`의 `OPENAI_BASE_URL`이 비어 있어 지문의 접속 주소 항목이 `None`이었다. 지문은 기준과 같았다.
- 로그의 `Failed to export spans` 줄은 스크립트가 Langfuse 주소를 일부러 비워서 나는 것이다.
- 세션이 사용량 한도에 걸려 멈췄지만, 백그라운드로 돌린 실험은 계속 진행되어 끝났다.
