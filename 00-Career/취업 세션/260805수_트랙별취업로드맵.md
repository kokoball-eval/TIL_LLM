1) 취업 지원 세션 내용

## 세션의 핵심 목적 (Private LLM Infra Engineer)
- 모델을 직접 만드는 연구자보다, 오픈소스 모델이나 상용 API를 인프라 위에 올려 실제 회사 업무에서 '빠르고, 싸고, 안정적으로 돌아가게 만드는 엔지니어'의 역할과 채용 시장 요구사항을 파악하는 세션

## 직무 및 채용 시장 분석 (Why LLM Infra?)
- 시장 변화: 
AI 기능 붙이기가 기존 3단계(API 호출)에서 8단계+(선정·서빙·RAG·평가·배포·관측)로 복잡해지며 통째로 새 직무화됨

- 기업의 내부 도입 이유: 
금융/의료/제조 등의 규제·보안(망분리), API 과금 부담(비용), 도메인 자산화(데이터 주권)

- 채용 현실: 
채용 공고의 80%가 경력 3년 이하 지원 가능하며 석사 요건은 4%에 불과함 (모델 연구보다 서빙·운영 직무가 압도적)

## 핵심 기술 스택 및 실무 (How to Work)
- 모델 선정/양자화: 
VRAM 크기, 상업 라이선스, 한국어 성능 기준으로 7B~14B 모델 선정 후 4bit 양자화로 메모리 효율화

- 서빙 최적화: 
vLLM을 활용해 PagedAttention(메모리 페이징), 연속 배치(Continuous Batching), Prefix Caching 기법 적용

- RAG & 파이프라인: 
권한을 고려한 문서 수집, 청킹, 한국어 임베딩/리랭킹, 정확한 출처 명시 및 LLM-as-judge 기반 자동 평가 구축

- LLMOps & 배포: 
GPU 메모리 제약을 고려한 카나리/섀도 배포, Prometheus-Grafana 기반 관측, 비용 모니터링

## 포트폴리오 & 면접 전략 (How to Express)
- 튜토리얼 벗어나기: 
"RAG 챗봇을 만들었다"가 아니라 "현장의 특정 불편을 어떤 기준으로 해결했는지" 문제 중심으로 접근

- 깊이 있는 1개 프로젝트: 
얕은 프로젝트 여러 개보다, 서빙부터 운영/평가까지 끝까지 끌고 가 꼬리 질문을 버틸 수 있는 1개 프로젝트 구축

- 숫자로 증명하는 README: 
"청크 크기 조정으로 정답률 61%→78% 개선", "양자화 후 지연시간 단축" 등 Before/After 수치 서술

- 경력 번역: 
기존 인프라/백엔드/QA/도메인 경력을 GPU 자원 운영, 서빙 처리량 튜닝, RAG 검색 품질 평가 역량으로 재해석

## 2. 느낀점
- 과거 경험의 강력한 재발견: 지난 8년간 쌓아온 QA 및 프로세스 구조화, 트러블슈팅 경험이 버려지는 것이 아니라, 
LLM 서빙의 안정성과 성능 최적화(vLLM, RAG 평가)를 이끄는 핵심 무기가 됨을 확인

- '기술'에서 '판단'으로의 관점 전환: AI가 코드 초안을 대신 작성해 주는 시대일수록 "무엇을 썼는가"보다 
"어떤 문제와 기준을 가지고 기술을 판단·검증했는가"를 보여주는 것이 진짜 실력임을 깨달음

- 명확한 전향 로드맵 확립: 복잡한 이론에 눌리지 않고, 내가 아는 현장의 문제를 하나 정해 
'서빙-RAG-평가' 한 바퀴를 끝까지 돌려 숫자로 기록하는 포트폴리오를 빠르게 구축하겠다는 실행 목표를 세움
