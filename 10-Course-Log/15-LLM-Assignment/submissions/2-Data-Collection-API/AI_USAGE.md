# AI 사용 기록

AI는 개념 질문과 직접 작성한 코드의 디버깅에만 사용할 수 있습니다. 사용하지 않았다면 아래에 `사용하지 않음`이라고 적습니다. 사용량을 늘릴 필요는 없습니다.

| 허용되는 도움 | 예시 |
|---|---|
| 개념 이해 | HTTP 404와 422의 차이, await의 의미를 다른 예시로 설명해 달라고 질문 |
| 자신의 코드 디버깅 | 직접 작성한 짧은 함수와 오류를 보여 주고 원인과 확인 방법을 질문 |

과제 전체 풀이, TODO의 완성 코드, 참고 답안을 요청하지 않습니다. 디버깅 답변도 이해한 원인과 수정 내용을 자신의 말로 기록하고 다시 실행합니다. API 키, `.env`와 인증 헤더를 질문에 포함하지 않습니다.

## 사용 여부

- 사용 여부: 사용함
- 사용한 도구: Claude Code (Claude Opus 5.5, Claude 데스크톱 앱)
- 사용 방식: 비전공자로서 파일 구조와 개념 설명을 먼저 받고, 빈칸마다 힌트를 받아 직접 입력한 뒤 AI가 `run`/`check` 결과를 확인했습니다.
- 범위에 대한 솔직한 기록: 필수 1~2는 개념 설명과 `____ in ____` 같은 빈칸 틀 위주로 도움을 받았습니다. 필수 3~4는 빈칸 틀과 함께 넣을 값까지 안내받아 직접 입력했으므로, 허용 범위(개념 질문, 디버깅)보다 더 많은 도움을 받았습니다. AI가 파일을 직접 수정한 것은 오타 수정, 지우라고 안내된 `support.todo` 줄 삭제, 제가 쓴 작성 메모 문장 붙여 넣기뿐입니다.

## 도움 기록

도움을 받은 건마다 표의 행을 추가합니다. 대화 전문보다 질문과 직접 확인한 결과를 구체적으로 적습니다.

| 단계/함수 | 직접 시도한 내용과 문제 | 질문 요약 | 받은 설명 | 내가 수정하거나 확인한 내용 | 재실행 결과 |
|---|---|---|---|---|---|
| 전체 | 과제 파일이 많아 무엇을 해야 하는지 몰랐음 | 파일 구조와 과제 의도, 필요한 개념 설명 요청 | app.py만 수정, API/HTTP 상태 코드/JSON/페이지네이션/Pydantic/await/재시도/요청 제한 개념을 예시로 설명받음 | `uv sync --frozen`, `demo`로 환경 확인 | Python 3.12.13, demo 정상 |
| 필수 1 `collect_releases` | params에 숫자 1, 5를 직접 넣었고, `"next"` 판단식의 순서가 바뀌고 따옴표가 빠졌고, 저장 칸에 파일 이름을 넣음 | 변수와 dict, `in` 사용법 질문 | 숫자를 직접 쓰면 2페이지에도 1페이지를 요청하게 되므로 반복 변수 `page`를 써야 함. `in`은 "앞이 뒤 안에 있나" 순서. 저장할 내용은 `value` 상자 | 직접 page/per_page 변수, `raise_for_status()`, `"next" in response.links`, `value`로 수정. 작성 메모는 직접 쓰고 표현 피드백만 받음 | `check collect` 9/9 통과, `run collect --live` 성공(2페이지, limited=true) |
| 필수 2 `normalize_releases` | 제목 대체에서 `tag_name`을 변수처럼 썼고 `item.get("item")`으로 잘못 꺼냄, 중복 ID 줄에 조건을 두 번 붙여넣음 | 빈 본문, 중복, 제목 대체, 플래그 자료형 판단 방법 | `==`와 `in` 사용법, `A if 조건 else B` 문법, None에 `.strip()`을 하면 오류가 나므로 `name and name.strip()`으로 먼저 확인, `type(x) is not bool` | 7개 빈칸 직접 입력. `bdoy` 오타는 AI가 수정. 작성 메모는 제 문장에 AI가 "두 시각은 다를 수 있다"는 표현을 덧붙여 넣음 | `check documents` 22/22 통과, 채택 3/격리 5/제외 2 확인 |
| 필수 3 문서 API | 모델 필드 선언 방법을 몰랐음, `min_length=1~3`처럼 잘못 쓰고 category에 값을 잘못 넣음 | 모델 필드와 404/409/422 구분 | 빈칸 틀과 넣을 값(LIMITS 키, Literal 값, 길이 1~3/64, bool)을 안내받음. 모델은 입력 검사표로 형식 오류는 422, 없는 ID는 404, 중복은 409 | 직접 입력 후 오류 4곳을 줄 번호 안내대로 수정. `source.url` 오타 수정과 `support.todo` 줄 삭제는 AI가 함. 작성 메모는 직접 씀 | `check document-api` 7/7 통과 |
| 필수 4 모델 연결 | 무엇을 넣어야 하는지 몰랐음 | 질문과 문서 묶기, 응답 JSON, 출처 검사 | 빈칸 틀과 넣을 변수를 안내받음. LLM이 보여 주지 않은 문서를 출처로 대는 것을 막는 검사라는 설명 | 3개 직접 입력 | `check query` 6/6 통과 |
| 필수 4 실패 처리 | 함수 이름 줄에 `attempt == 0`을 실수로 붙여넣어 문법 오류 | 재시도 조건과 공급자 429 처리 | 첫 시도(attempt 0)의 timeout과 5xx만 재시도, 공급자 429는 503으로 전달. 빈칸 값도 안내받음 | 3개 직접 입력, 문법 오류는 AI가 원래 이름으로 수정. 작성 메모는 직접 씀 | `check retry` 17/17 통과 |
| 필수 4 요청 제한과 기록 | - | 고정 구간 제한과 로그 필드 | 첫 요청이거나 window가 지나면 초기화, count가 limit에 도달하면 거부, 로그에는 다섯 필드만. 빈칸 값도 안내받음 | 4개 직접 입력 | `check observe` 6/6, `check all` 67/67 통과 |
| 실행 확인 | 서버 요청과 실제 모델 확인 방법을 몰랐음 | 안내에서 권장한 서버 확인과 live 확인 진행 요청 | AI가 서버를 실행해 요청을 보내고 결과를 설명함. `.env`의 API 키는 제가 직접 입력했고 AI에게 보여 주지 않음 | 등록 201, 재등록 409, `manual/a` 422, 없는 ID 404를 확인. 경계값으로 제목 300자는 201, 301자는 422임을 확인. 로그에 method/path/status/mode/elapsed_ms만 남는 것 확인. live 답변을 policy-python 본문과 대조 | `run query --live` 200, 모델 1회 호출, 답변 내용이 policy-python 본문과 일치 |
