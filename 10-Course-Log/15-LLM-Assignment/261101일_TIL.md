## 💡 오늘의 학습 총평

- **오늘 나온 약어·용어 정리**

  | 약어·용어 | 풀스펠링 | 한 줄 뜻 |
  |---|---|---|
  | API | Application Programming Interface | 프로그램끼리 대화하는 창구. 주소·형식·필드가 문서로 약속돼 있다 |
  | HTTP GET / POST | HyperText Transfer Protocol | 달라고 요청(조회) / 받아 달라고 전달(등록·질문) |
  | JSON | JavaScript Object Notation | 주고받는 데이터 형식. 파이썬 dict·list와 거의 같은 모양 |
  | 페이지네이션 | Pagination | 자료를 `page`, `per_page`로 나눠 받는 방식. 다음 페이지는 `response.links`의 `"next"` |
  | `raise_for_status()` | — | 4xx·5xx 응답이면 **오류를 일으킴**. 안 부르면 실패 응답도 조용히 통과 |
  | 채택 / 격리 / 제외 | kept / quarantine / excluded | 사용 가능 / 대상은 맞는데 내용이 망가짐 / 애초에 대상이 아님(초안·프리릴리스) |
  | Pydantic 모델 | — | 입력 **검사표**. 필드와 조건을 선언하면 형식 오류는 자동으로 422 |
  | `Literal[...]` | — | "이 값들 중 하나만" 허용 (category 5개 / 답변용 4개) |
  | 404 / 409 / 422 | HTTP 상태 코드 | 그런 문서 없음 / 같은 ID·URL이 이미 있음 / 요청 형식 자체가 틀림 |
  | 502 / 503 / 504 | HTTP 상태 코드 | 위쪽 서버가 이상함 / 지금 이용 불가 / 위쪽 서버가 너무 느림 |
  | `async` / `await` | asynchronous | 기다리는 동안 서버가 **다른 요청도 처리**할 수 있게 하는 표시 |
  | 고정 구간 요청 제한 | Fixed Window Rate Limit | 60초마다 카운터를 0으로 되돌리고 그 안에서 30번까지만 받음 |
  | `Retry-After` | — | 429 응답에 붙는 "몇 초 뒤에 다시 오세요" 헤더 |
  | fixture / live | — | 고정 테스트 자료와 모델 대역 / 실제 GitHub·OpenAI 호출 |

- **핵심 통찰: 원본은 그대로 두고, 검사를 통과한 것만 새로 만든다**
  - 수집 단계는 받은 원본을 **수정하지 않고** `raw_pages.json`에 그대로 저장한다. 정제 단계는 원본을 읽어 **새 문서**를 만든다.
  - 원본을 고쳐 버리면 "왜 이 릴리스가 빠졌지?"를 나중에 추적할 수 없다. 그래서 격리·제외 기록에 page, row, id, reason을 남긴다.
  - 분류 순서도 중요하다. 초안이면서 본문도 빈 행은 **"대상 아님(제외)"이 먼저**다. 범위 판단 → 내용 검사 순서.

- **두 번째 통찰: 오류 코드는 "누가 막았나"로 갈린다**

  | 상황 | 누가 막나 | 코드 |
  |---|---|---|
  | 형식이 틀림 (글자 수 초과, ID에 `/`, 필드 누락) | Pydantic 모델 | 422 |
  | 형식은 맞는데 그런 번호가 없음 | `find_document` | 404 |
  | 이미 같은 번호나 주소가 있음 | `register_document` | 409 |
  | 우리 서버 한도 초과 | `admit_query` | 429 |
  | 공급자(OpenAI)가 429 | `query_with_retry` | **503**으로 바꿔 전달 (손님 잘못이 아니므로) |

  - GET은 ID를 **주소**에, POST는 문서를 **본문(JSON)**에 담는다.
  - 422·404는 모델을 부르지 않으니 요청 제한 횟수에도 넣지 않는다.

- **세 번째 통찰: LLM 답변은 그대로 믿지 않는다 (과제 1·3과 같은 결론)**
  - 모델이 준 글자를 `json.loads`로 dict로 바꾸고 → `QueryReply`로 형식 검사 → 출처 ID가 **우리가 보여 준 문서 안에 있는지** 검사한다.
  - 재시도는 **첫 시도의 timeout·5xx만, 딱 한 번**. 401 같은 4xx는 다시 해도 똑같이 실패하고, 재시도를 늘리면 비용과 장애가 커진다.
  - `check all` 통과 ≠ 답변이 사실. live 답변은 근거 문서(`policy-python`)와 **문장 단위로 직접 대조**했다.

- **향후 계획 및 다짐**
  - `app.py`, `AI_USAGE.md` 두 파일을 제출한다. `.env`는 제출하지 않고, 과제가 끝나면 키를 폐기한다.
  - 필수 3~4는 빈칸 모양과 값까지 안내받아 입력했다. 힌트 없이 다시 써 보면서 Pydantic 필드 선언과 `any(... for ... in ...)` 문법을 내 것으로 만든다.
  - 선택 심화(두 스냅샷 비교 `compare_snapshots`)는 이번엔 진행하지 않았다. 여유가 되면 혼자 힘으로 도전.

## 🧭 종합 QA 체크포인트

### 1. 경계값 테스트: 300자는 통과, 301자는 거부

| 요청 | 결과 |
|---|---|
| 제목 300자 | 201 |
| 제목 301자 | 422 |
| 문서 ID 3개 / 4개 | 정상 / 422 |

- 게임 QA의 경계값 테스트와 같다. 상한 **바로 그 값**과 **하나 넘는 값**을 같이 봐야 off-by-one이 잡힌다.

### 2. 숫자를 직접 쓰면 "첫 바퀴만" 맞는다

- `{"page": 1, "per_page": 5}`로 써도 1페이지는 정상이라 버그가 안 보인다. **2바퀴째**에 또 1페이지를 요청하면서 드러난다.
- 기본값(5)으로만 테스트하면 `per_page` 하드코딩도 안 보인다. 검사기는 다른 값을 넣어 본다.

### 3. None 먼저 확인하기

- `name.strip()`만 쓰면 이름이 아예 없는 행(None)에서 `AttributeError`로 멈춘다.
- `name and name.strip()` → 앞이 "없음"이면 뒤를 실행하지 않는다. 문을 열기 전에 문이 있는지부터 확인.

### 4. 안전한 로그

- 로그에는 `method, path, status, mode, elapsed_ms` 다섯 개만. 경로도 `support.safe_route`로 `/documents/{doc_id}`처럼 **양식만** 남긴다.
- 실제 서버 로그를 확인해 보니 질문·본문·키가 한 줄도 찍히지 않았다.

### 5. Claude가 짚어준 확인 포인트

- **파일 이름(어디에) ≠ 저장할 내용(무엇을)**: `json.dump(무엇을, 어디에)`의 첫 칸에는 `value` 상자.
- **만든 적 없는 이름은 못 쓴다**: `tag_name`은 상자로 만든 적이 없으니 `item.get("tag_name")`으로 원본에서 꺼낸다.
- **Windows Git Bash curl은 한글 본문을 깨뜨린다**: 서버가 400을 냈지만 서버 문제가 아니었다. Python(httpx)으로 다시 보내니 201·409·422가 정상으로 나왔다.

## 1. 필수 1 — 공개 자료 수집 (`collect_releases`)

- 빈칸 4개:
  - 페이지와 크기: `{"page": page, "per_page": per_page}` (숫자가 아닌 **변수**)
  - HTTP 상태 검사: `response.raise_for_status()` (이름 뒤 `()`를 붙여야 **실행**)
  - 다음 페이지 확인: `"next" in response.links` (`찾을것 in 찾을곳` 순서, 글자는 따옴표)
  - 저장할 데이터: `value` (반복문이 `pages`, `report`를 차례로 담는 상자)
- 결과: `check collect` 9/9. 2페이지에서 503, timeout, 배열이 아닌 응답도 모두 "중단 + 실패 페이지 기록"으로 통과.
- live: 실제 GitHub에서 2페이지 × 5개 = 10개 수집, `limited=true` (더 있지만 상한에서 멈춤 = 전체 이력 아님).

## 2. 필수 2 — 품질 점검과 문서 구성 (`normalize_releases`)

- 빈칸 7개:
  - 플래그 자료형: `type(item.get("draft")) is not bool or ...` (`isinstance(True, int)`가 True라서 `type(...) is bool`로 엄격하게)
  - 제목 대체: `name if name and name.strip() else item.get("tag_name")` (`A if 조건 else B`)
  - 빈 본문: `body == ""` (`=`는 넣기, `==`는 묻기)
  - 중복 ID: `raw_id in accepted_ids`
  - 문서 값: 정리를 마친 `body`, `source_url`, 이번 수집시각 `collected_at`
- 결과: fixture 10건 → 채택 3(`release-uv-101`, `102`, `109`) / 격리 5 / 제외 2, `check documents` 22/22.
- 잘못된 첫 행(109, 본문이 숫자) 뒤에 온 같은 ID의 정상 행은 채택된다. 내용이 유효한 행만 ID를 채택하기 때문.
- live 자료 10건은 전부 채택 (실제 자료는 깨끗했다. fixture 건수를 정답으로 쓰지 않는다).

## 3. 필수 3 — 문서 API

- 모델 필드 9개:
  - `Document`: `body`(1~20,000자), `source_url`(1~2,048자), `collected_at: str`, `category: Literal[5개]`
  - `QueryRequest`: `document_ids: list[DocumentId]`(1~3개), `session_id`(기본 `"demo"`, 1~64자)
  - `QueryReply`: `source_ids: list[DocumentId]`, `needs_human: bool`, `category: Literal[4개]` (release 없음)
- `find_document`: `doc_id not in store` → 404
- `register_document`: `document.doc_id in store` 또는 `any(d.source_url == document.source_url for d in store.values())` → 409
- `response_models`: 단건은 `Document`, 질문은 `QueryReply` → `/docs` 스키마에 표시됨
- 결과: `check document-api` 7/7. 서버 직접 요청: 등록 201 → 조회 200 → 재등록 409 → 같은 URL 다른 ID 409 → `manual/a` 422 → 없는 ID 404.

## 4. 필수 4 — 모델 연결 (`build_prompt`, `call_model_once`)

- `{"question": question, "documents": selected}`로 묶어 JSON 문자열로 전달
- `QueryReply.model_validate(json.loads(text))`
- 출처 검사: `any(i not in selected_ids for i in reply.source_ids)` → 선택하지 않은 문서를 출처로 대면 거부
- 결과: `check query` 6/6.
- live (`gpt-5.6-luna`, 2.8초, 1회 호출): Python 3.12 기준, `uv python install 3.12`, `uv sync --python 3.12`, 가상환경 복사 금지, PowerShell·macOS/Linux, CPU 실행, 확인되지 않은 버전 호환성 보장 안 함 → **`policy-python` 본문과 6개 항목 모두 일치**, 출처도 `policy-python`.

## 5. 필수 4 — 실패 처리 (`query_with_retry`)

| 상황 | 최종 응답 | 모델 호출 |
|---|---|---|
| 첫 timeout 또는 5xx 뒤 성공 | 200 | 2회 |
| timeout 두 번 / 5xx 두 번 | 504 / 502 | 2회 |
| 공급자 429 | 503 | 1회 |
| 401 등 다른 4xx, JSON·출처 오류 | 502 | 1회 |

- 빈칸: `attempt == 0` / `attempt == 0 and 500 <= status <= 599` / `503`
- 결과: `check retry` 17/17.

## 6. 필수 4 — 요청 제한과 기록 (`admit_query`, `request_logging`)

- 구간 갱신: `state["start"] is None or now - state["start"] >= window` (`start=0`도 정상 시각이라 `is None`으로 확인)
- 한도 확인: `state["count"] >= limit` → 남은 초를 올림해 반환 → 429 + `Retry-After`
- 요청 수 증가: `1` (모델 재시도는 여기로 돌아오지 않아 추가로 세지 않음)
- 로그 필드: `method, path, status, mode, elapsed_ms`
- 결과: `check observe` 6/6 (느린 요청 3개의 대기가 겹치는지도 확인), **`check all` 67/67**.
