## 💡 오늘의 학습 총평

- **오늘 나온 약어·용어 정리**

  | 약어·용어 | 풀스펠링 | 한 줄 뜻 |
  |---|---|---|
  | RAG | Retrieval-Augmented Generation | 문서를 검색해 근거로 넣고 답하게 하는 구성 |
  | 청크 (chunk) | — | 검색 단위로 자른 문서 조각. 이번엔 **문단 하나**가 청크 하나 |
  | 임베딩 / 정규화 | embedding / normalization | 문장을 숫자 묶음(벡터)으로 바꾸기 / 길이를 1로 맞춰 방향(뜻)만 비교 |
  | `passage:` / `query:` | — | E5 모델 규칙. 문서에는 `passage:`, 질문에는 `query:`를 붙인다 |
  | `PointStruct` | — | Qdrant에 넣는 한 점. 번호(`id`) · 위치(`vector`) · 설명 정보(`payload`) |
  | `Filter(must=[...])` | — | 검색 **전에** 후보를 거르는 조건 묶음. must = 모두 만족 |
  | Golden Dataset | — | 질문 · 정답 · 근거 문서를 미리 정해 둔 평가 사례 |
  | Recall (문서) | — | 필요한 문서 중 찾은 비율. 필요한 문서가 없으면 `None` |
  | Context Engineering | — | 모델 입력에 **무엇을, 어떤 순서로, 얼마나** 넣을지 설계 |
  | developer / user 역할 | — | 고정 지시는 developer, 자료와 질문은 user. 자료가 지시를 덮어쓰지 못하게 분리 |
  | 장기 기억 / 세션 상태 | — | 사용자별로 남는 `records` / 대화가 끝나면 사라지는 `turns` |
  | 입력 예산 | — | `limit - reserve - margin`. 출력 자리와 안전 여유를 빼고 남는 입력 칸 |
  | Prompt Caching | — | 매번 같은 앞부분(prefix)을 저장해 두고 재사용해 비용을 줄임 |
  | SHA-256 | Secure Hash Algorithm 256-bit | 같은 재료면 항상 같은 값, 한 글자만 달라도 다른 값 |

- **핵심 통찰: RAG는 "검색을 잘하는 것"보다 "검색하면 안 되는 것을 먼저 거르는 것"이 먼저다**
  - 옛날 VPN 문서는 저장은 되지만 검색에는 나오면 안 된다. 그래서 점수 계산 **전에** `status == current`, `category`로 거른다.
  - Context Engineering도 같았다. 우선순위가 높아도 **접근 권한 밖이거나 만료된 자료면** 입력에 넣으면 안 된다. 거르기 → 순서 정하기.
  - 게임 QA로 보면: 지난 빌드의 버그 리포트는 아카이브에는 남기되, 이번 빌드 검증 목록에는 안 넣는 것과 같다.

- **두 번째 통찰: 줄이는 방법에 따라 같은 토큰으로도 결과가 완전히 달라진다**
  - 최근 대화만 남긴 것과 요약+최근은 추정 토큰이 **둘 다 1744**로 같았는데, 사실 3개 일치는 **0개 vs 3개**였다.
  - 토큰을 줄이는 게 목적이 아니라, **사라지면 안 되는 사실을 남긴 채** 줄이는 게 목적이다.

- **세 번째 통찰: 캐시는 첫 사용에서 오히려 비싸다**
  - 비사용 0.0003066 → 첫 사용 0.000368(캐시 쓰기 비용 때문에 상승) → 재사용 0.00008556(읽기 1228 토큰).
  - 한 번만 부를 요청이면 캐시가 손해일 수도 있다. "적용하면 무조건 이득"이 아니라 **재사용 횟수**를 같이 봐야 한다.

- **향후 계획 및 다짐**
  - 내일 LLMOps 과제(같은 질문으로 변경 전후 비교, Langfuse 기록)를 진행한다.
  - 선택 심화(RAG `fuse_rankings` RRF, CE `merge_summary` 변경 이력)는 이번엔 건너뛰었다. 필수 개념이 익숙해지면 다시 본다.
  - 아직 헷갈리는 것: `=`와 `:`(사전), `=`와 `==`, `>`와 `>=`(경계값), 따옴표가 있으면 글자 / 없으면 변수.

## 📊 어제보다 나아진 점

- 과제 1~3(PE, 데이터 수집, LangChain) 때 배운 **set 비교, `A if 조건 else B`, 객체 `.` vs 사전 `[""]`** 가 그대로 다시 나왔고, 이번엔 오류 메시지를 보고 고칠 수 있었다.
- 경계값 감각이 생겼다. "예산과 **같으면 포함**"이라는 조건을 보고 처음엔 `>=`로 썼다가, 같을 때 멈추면 안 된다는 걸 이해하고 `>`로 고쳤다. QA의 경계값 분석(BVA) 그대로다.
- `--live`(유료) 결과를 **직접 읽고** 관측 주석을 썼다. 숫자를 옮기는 게 아니라 "무엇이 빠졌고 왜 그 방식을 골랐는지"를 적었다.

| CE | `run cache --live` | 캐시 쓰기 1228, 읽기 1228. 비용 0.0003066 / 0.000368 / 0.00008556 |

### 2. 평가 사례(Golden Dataset)는 "정답 문서"를 바꿔서 점수를 올리면 안 된다

- `make_golden`에 답이 있는 사례(`given-firewall` → `vpn`, 핵심 문구 "보안팀")와 자료가 없는 사례(`given-unknown` → 보류가 정답)를 하나씩 직접 정했다.
- 원문 ID(`vpn`)와 청크 ID(`vpn:0`)는 다르다. 평가 사례에는 원문 ID, 답변 출처에는 청크 ID.
- 테스트 케이스의 기대 결과를 실제 결과에 맞춰 고치면 테스트가 아니게 되는 것과 같다.

### 3. 보조 지표의 한계를 같이 적는다

- `answer_check`는 핵심 문구가 들어 있는지와 보류 여부만 본다. **사실성까지는 판정하지 못한다**.
- 사례 2~4개, `top_k=1` 조건이라 일반화하기 어렵다. 변환 후 질문이 "API 토큰를"처럼 조사가 어색해지는 부작용도 있었다.

### 4. 오염 자료가 최종 입력에 없는지 확인

- `select_context`가 거른 `tainted-document`(오염 문서)와 `unverified-tool`(검증 안 된 도구 결과)이 캐시 실행의 최종 입력에도 없는 것을 확인했다.

### 5. Claude가 짚어준 확인 포인트

- **추정 토큰과 실제 토큰은 다르다**: `estimated_input_tokens`는 프로그램이 센 값, `usage.input_tokens`는 모델이 계량한 값.
- **전체 대화의 한도는 다른 두 조건과 다르다**: 전체 대화는 한도 5000으로 실행되어 3개 모두 맞혔다. 1999가 넘는 건 2300 한도(예산 1788) 기준일 때 이야기.
- **줄 번호는 매번 다시 확인한다**: 주석을 한 줄 넣으면 아래 줄 번호가 밀린다.

## 1. RAG 필수 1 — 문서를 저장하고 현행 자료만 검색

```python
text = " ".join(paragraph.split())                                   # 연속 공백 → 한 칸
"chunk_id" : f"{document["document_id"]}:{number}"                   # vpn:0, vpn:1 ...
vectors = embedder.encode(texts, normalize_embeddings=True)          # 정규화된 문서 벡터
point = models.PointStruct(id=i, vector=list(vector), payload=row)   # vector는 list로
condition_a = models.FieldCondition(key="status", match=models.MatchValue(value="current"))
condition_b = models.FieldCondition(key="category", match=models.MatchValue(value=category))
scope = models.Filter(must=[condition_a, condition_b])
```

- 문단 단위로 자르면 근거를 찾을 때 너무 길거나 짧지 않다.
- 메타데이터를 남기는 이유: `status`, `category`는 검색 필터, `chunk_id`는 출처, `document_id`는 필요한 문서 확인.

## 2. RAG 필수 2 — 별칭 변환과 답변 비교

```python
rewritten = rewritten.replace(alias, formal_name)                          # "초록문" → "VPN 원격 접속"
context = "\n\n".join([f"[{row["chunk_id"]}] {row["text"]}" for row in rows])
if any(citation not in allowed for citation in reply["citations"]):       # 검색 안 한 출처 하나라도
recall = len(expected & found) / len(expected) if expected else None
```

- 별칭은 **검색용 질문에만** 적용하고, 답변 생성에는 원질문을 유지한다.
- `any` = 하나라도, `all` = 전부. 출처 검사는 "하나라도 이상하면 막기"라서 `any`.
- 관측: `given-firewall`이 변환 전에는 door 문서를 검색해 검색 누락, 변환 후에는 vpn 문서를 검색. 악화 사례는 없음.

## 3. CE 필수 1 — 자료 선별, 기억, 메시지

```python
allowed = (
    (item["user_id"] == "public" or item["user_id"] == user_id)
    and item["trusted"] and item["active"]
    and (item["expires_at"] is None or item["expires_at"] > now)
)
return copy.deepcopy(records.get(key))        # read: 없으면 None
records[key] = copy.deepcopy(value)           # create / update
return records.pop(key, None)                 # delete: 없어도 오류 없이
return [{"role": "developer", "content": prefix}, {"role": "user", "content": data}, *history,
        {"role": "user", "content": question}]
```

- `and`가 `or`보다 먼저 계산된다 → `or` 조건은 **괄호로 묶는다**.
- `deepcopy`: 저장소 안의 값을 그대로 내주면 바깥에서 바꿔 버릴 수 있다. 원본 세이브 파일을 직접 넘기지 않고 복사본을 주는 것.
- `*history`: 대화 메시지 목록을 **풀어서** 그 자리에 끼워 넣는다.

## 4. CE 필수 2 — 요약, 예산, 캐시 키

```python
summary[name] = {"value": value, "source_turn_id": turn["id"]}     # 같은 항목은 덮어써서 최신 값
budget = limit - reserve - margin
if count(make_messages(candidate)) > budget:                       # 같으면 포함, 넘으면 멈춤
return hashlib.sha256(f"{user_id}\n{prefix}".encode("utf-8")).hexdigest()
```

- 요약은 값과 **출처 턴 ID**를 함께 남긴다 → 나중에 원문 대조가 가능.
- 캐시 키에는 사용자 ID와 고정 지시만 넣고 **질문은 넣지 않는다** (매번 달라지면 재사용 불가).
- `\n`을 넣는 이유: `"ab" + "c"`와 `"a" + "bc"`가 같은 글이 되는 충돌을 막는다.

## ⚠️ 오늘의 함정 모음 (재발 방지용)

| # | 함정 | 왜 틀렸나 | 올바른 방법 | 근거 |
|---|---|---|---|---|
| 1 | 사전에 `"k" = v` | 사전 안은 `:`. `=`는 함수의 이름표 인자 | `{"k": v}` | RAG 1 |
| 2 | f-string 안 따옴표 짝이 안 맞음 | 바깥 따옴표가 중간에 닫힘 | 따옴표 짝 확인 | RAG 1 |
| 3 | `alias`, `formal_name`에 따옴표 | 따옴표가 있으면 글자 자체 | 변수는 따옴표 없이 | RAG 2 |
| 4 | `filter(...)` | 대소문자가 다르면 다른 이름 | `models.Filter(...)` | RAG 1 |
| 5 | 조건을 `{ }`로 묶음 | 중괄호는 집합(set)이 됨 | 소괄호 `( )` | CE 1 |
| 6 | `or`에 괄호 없음 | `and`가 먼저 계산돼 뜻이 바뀜 | `(A or B) and C` | CE 1 |
| 7 | `deepcopy(a, b)` | 인자는 하나 | `copy.deepcopy(value)` | CE 1 |
| 8 | 사전 안에 `"*history"` | 글자가 되어 버림 | 목록 안에 `*history` 그대로 | CE 1 |
| 9 | `turn_id`, `turn` 전체 | 실제 칸 이름은 `id` | `turn["id"]` (데이터 파일에서 확인) | CE 2 |
| 10 | `>= budget` | 같을 때도 멈춤 | `> budget` (같으면 포함) | CE 2 |
| 11 | 캐시 키에 `\n` 누락 | 다른 조합이 같은 글이 될 수 있음 | `f"{user_id}\n{prefix}"` | CE 2 |
