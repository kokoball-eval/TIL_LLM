## 💡 오늘의 학습 총평

- **오늘 나온 약어·용어 정리**

  | 약어·용어 | 풀스펠링 | 한 줄 뜻 |
  |---|---|---|
  | LCEL | LangChain Expression Language | `A \| B \| C`처럼 단계를 파이프로 잇는 LangChain 문법 |
  | Runnable | — | LangChain의 모든 부품이 따르는 공통 규격. `invoke`, `batch`, `stream` 버튼이 있다 |
  | `Document` | — | 검색용 문서 한 장. 본문(`page_content`) + 정보(`metadata`). 버그 티켓의 Description + 필드 |
  | `RunnableParallel` | — | 같은 입력을 여러 작업에 **동시에** 보내고 이름표 붙여 모음 |
  | `RunnablePassthrough` | — | 입력을 손대지 않고 그대로 통과 (원본 보존) |
  | `RunnableBranch` | — | 조건에 따라 갈림길 (if문). 문서 없으면 모델 호출 없이 안내 |
  | `PydanticOutputParser` | — | AI 답변 글을 정해진 양식(`Answer` 4칸)으로 검수·변환 |
  | `MessagesPlaceholder` | — | 프롬프트에 **대화 묶음을 통째로** 끼워 넣는 자리 |
  | `InMemoryChatMessageHistory` | — | 세션별 대화 기록. 메모리에만 있어 프로그램을 끄면 사라짐 |
  | `with_retry` / `with_fallbacks` | — | 허용된 오류만 재시도 / 그래도 실패하면 대체 안내 |
  | `stream` vs `invoke` | — | 조각조각(라이브 방송) vs 완성본 한 번(녹화 방송) |
  | delta / reset / final | — | 검증 전 임시 조각 / 앞 조각 폐기 공지 / 검증된 최종 답 |
  | Callback | — | 단계가 시작·끝날 때 자동 호출되는 기록원 (`TraceHandler`) |
  | `yield` | — | 값을 내보내고 함수는 **계속** 진행 (`return`은 내보내고 끝) |
  | `None` | — | 파이썬의 "없음, 빈칸". `is None` / `is not None`으로 확인 |

- **핵심 통찰: AI 답변은 그대로 믿지 않고, 시스템으로 감싼다**
  - 과제 3의 다섯 문제는 결국 하나의 질문이다. "AI 답변을 어떻게 **믿을 수 있게** 만드나?"
  - 검색(근거를 준다) → 양식 검수(parser) → 근거 검수(`validate_sources`) → 기억(대화 이력, 검증된 것만) → 실패 대비(재시도, fallback) → 관측(실행 기록).
  - 1번 과제는 이걸 **프롬프트와 직접 짠 반복문**으로 했고, 이번엔 **LangChain 부품을 조립**해서 했다. 개념은 같고 도구만 다르다.

- **두 번째 통찰: 게임 QA 비유로 보면 다 아는 개념이다**

  | LangChain | 게임 QA |
  |---|---|
  | `Document` (page_content + metadata) | 버그 티켓 (Description + 필드) |
  | `RunnableParallel` | QA 두 명이 동시에: 원본 보관 / 문서 검색 |
  | `prompt \| model \| parser` | 빌드 파이프라인 (순서가 바뀌면 안 됨) |
  | 세션별 이력 | 플레이어별 세이브 파일 (A의 진행이 B에 섞이면 버그) |
  | primary만 저장 | 클리어했을 때만 세이브 (게임오버 상태를 세이브하지 않음) |
  | `with_retry` / `with_fallbacks` | 접속 실패 시 자동 재시도 → 그래도 안 되면 안내 팝업. 비밀번호 오류는 재시도 안 함 |
  | delta / reset / final | 라이브 자막 / "앞 자막 무시" 공지 / 확정 자막 |
  | `TraceHandler` | 크래시 로그 (단계, 소요 시간, 예외 이름) |
  | `--scenario midstream` | 서버 끊김 강제 재현 |

- **세 번째 통찰: 이미 자막을 보냈다면 재시도하지 않는다**
  - 방송 **시작 전** 오류 → 조용히 재시도 (시청자는 모름). 로그 스팸이 8줄 → 10줄로 늘어난 게 재시도 흔적이었다.
  - 방송 **도중** 오류 → 재시도하면 앞 자막과 새 자막이 겹친다 → `reset` 후 `fallback`.
  - 그래서 재시도 조건이 `not sent_delta and attempt == 0`. 필수 4는 2회 시도였지만 midstream은 **1회**에서 끝났고, trace의 `model_attempts=1`로 확인했다.

- **향후 계획 및 다짐**
  - `AI_USAGE.md` 맨 아래 "최종 코드와 설명을 스스로 설명할 수 있는지 확인"을 **직접** 쓰고 `main.py`, `AI_USAGE.md` 두 파일을 제출한다.
  - 여유가 되면 선택 심화(`review_draft`: 초안 검토 → 한 번 수정 → 재검토)와 `--live` 실행(chain, history, stream)으로 실제 AI 답변을 문서와 대조해 본다.
  - 이해가 덜 된 부분: `[x for x in 목록 if 조건]` 필터 문법, `A if 조건 else B` 한 줄 분기, 객체(`.`)와 dict(`[""]`) 구분. 튜터 질문에 대비해 다시 읽어 본다.

## 🧭 종합 QA 체크포인트

### 1. `run`은 수동 테스트, `check`는 자동 회귀 테스트

| 명령 | 역할 | 오늘 확인한 것 |
|---|---|---|
| `run search` | 사례별 expected vs actual | 5개 사례 모두 `matches=true` |
| `run history` | 세션 분리 | `employee-a` 4개, `employee-b` 2개 |
| `run recovery` | 고정 장애 주입 | 일시 오류 후 성공 2회, 두 번 실패 fallback 2회 |
| `run stream --scenario …` | 장애 재현 | 기본 / temporary / midstream 세 경로 |
| `check all` | 56개 자동 검사 | 56 / 0 |

### 2. 빈칸 메시지는 "실행 순서"대로 나온다

- 35번째 줄을 채운 뒤 48번째 줄 메시지를 기대했는데 81번째 줄이 먼저 나왔다.
- 이유: 검색 체인을 **먼저 조립(로딩)** 하고 실제 검색은 나중에 한다. 게임이 로딩 단계에서 멈추면 플레이 단계 버그는 아직 안 보이는 것과 같다.
- 메시지가 예측과 다르다고 틀린 게 아니다. 어느 단계에서 멈췄는지를 읽는다.

### 3. 로그 스팸도 정보다

- `TraceHandler` 빈칸이 남아 있을 때 `NotImplementedError in TraceHandler...`가 반복해서 찍혔다. 이건 경고만 하고 프로그램은 계속 돌았다.
- 빈칸을 하나 채울 때마다 스팸 **종류가 바뀌었다** (시작 시각 → 밀리초 → 오류 이름 → 청크 수). 어디까지 진행됐는지 보여 주는 지표였다.
- 조각 스팸이 delta와 **번갈아 7번** 나온 것 = 조각이 올 때마다 기록원이 세려고 했다는 증거.

### 4. trace에서 부모 run을 따라간다 (midstream)

```
122 request_summary  (run …7301)  route=fallback, model_attempts=1   ← 이번 요청 전체
 └─ 114 chain        (run …7308)  prompt | model
     └─ 119 model_error (부모 …7308)  chunk_count=1, error_type=TemporaryModelError
```

- Jira의 에픽 → 스토리 → 하위 작업처럼, `model_error`의 부모를 따라 올라가면 같은 요청의 요약에 닿는다. "이 오류가 이 fallback의 원인"임을 로그로 증명.
- `error_type`(240번째 줄)과 `chunk_count`(255번째 줄)는 내가 직접 채운 칸이라, 그게 있어야 이 리포트를 쓸 수 있다.

### 5. Claude가 짚어준 확인 포인트

- **`todo`를 지울 때 앞뒤에 남길 것을 먼저 본다**: `if …:`의 콜론, 목록 칸 끝 쉼표, `yield `, `return `, `state = {"started": … ,`.
- **이유 주석은 과제 문서의 힌트를 확인한다**: 필수 1은 "서로의 결과가 필요한지", "검색 함수를 교체해도 나머지가 유지되는지"가 채점 포인트였다. "역할이 달라서 나뉜다"는 원인이 아니라 결과를 다시 말한 것.
- **인과관계 순서**: "병렬이라서 교체가 쉽다"(X) → "서로의 결과가 필요 없어서 → 병렬도 되고 교체도 쉽다"(O).
- **기록은 본인이 실행한 결과로**: AI가 미리 돌린 `check` 수치는 직접 다시 실행해서 같은지 확인한 뒤 남긴다.

## 1. 필수 1 — 문서 검색

```python
document = Document(page_content=row["body"], metadata=metadata)
if document.metadata["doc_id"] not in allowed:          # 허용 후보 밖이면 Skip
score = len([word for word in words if word in normalized])   # 질문에 들어 있는 키워드 수
query = support.search_query(value["question"], value["history"])
parallel = RunnableParallel(original=preserve, documents=retrieve_chain)
```

- 키워드 점수 = Jira 필터 결과 **건수**. 목록이 아니라 `len()`으로 센 숫자여야 `score > 0` 비교가 된다.
- "그 버전" 같은 후속 질문은 `search_query`가 같은 세션의 이전 질문을 붙여 검색한다 (필수 3에서 확인).
- 이유 주석: 입력은 보존해서 검색 결과와 합칠 때 원래 질문을 쓰고, 검색은 따로 수행한다. 두 작업은 서로의 결과가 필요 없어 병렬 처리되고, 검색 방식이 바뀌어도 검색 쪽만 바꾸면 된다.

## 2. 필수 2 — 기본 체인

```python
parser = PydanticOutputParser(pydantic_object=support.Answer)   # 질문 양식(QueryInput) 아님!
MessagesPlaceholder("history"),
if len(answer.source_ids) != len(set(answer.source_ids)):                     # 중복 출처
if len([sid for sid in answer.source_ids if sid not in allowed]) > 0:          # 검색 안 한 출처
if len(answer.source_ids) == 0 and answer.needs_human == False:                # 근거 없는 확답
generate = prompt | model | parser
answer = validate_sources(value["parsed"], value["documents"])                 # 칸 순서: 답변, 문서
return len(value["documents"]) == 0                                            # 문서 없음 분기
```

- `=`는 저장, `==`는 비교, `!=`는 다른가.
- `and`는 둘 다, `or`는 하나만. 근거 없는 확답 검사를 `or`로 쓰면 "근거가 없어 담당자 확인 요청"한 **정상 답변까지** 반려된다.
- `run chain` 결과: `policy-python` 근거, `route=primary`, 답변 내용도 문서 본문과 일치.

## 3. 필수 3 — 대화 이력

```python
store[session_id] = InMemoryChatMessageHistory()              # 빈 세이브 파일 하나 찍어내기
if outcome["route"] != "primary":                             # 클리어 못 했으면 저장 안 함
messages = [HumanMessage(question), AIMessage(answer.answer)]  # [플레이어] → [NPC] 순서
```

- 이유 주석: 검색 문서는 답변의 근거(출처)로 쓰고, 대화 이력은 앞에서 무슨 얘기를 했는지 이해하는 데 쓴다. primary만 저장해야 불필요한 데이터가 누적되지 않고, 검증된 답변만 다음 질문의 맥락이 된다.
- 실패 답변을 저장하면 다음 질문 때 AI가 그걸 "확정된 대화"로 믿고 이어 간다. 버그 난 세이브를 불러오는 것과 같다.

## 4. 필수 4 — 실패 복구

```python
retry = primary.with_retry(retry_if_exception_type=support.RECOVERABLE, stop_after_attempt=2, wait_exponential_jitter=False)
return retry.with_fallbacks([fallback], exceptions_to_handle=support.RECOVERABLE)
```

- `support.RECOVERABLE`: 일시 오류, timeout, 5xx, 파싱 오류, 출처 오류 → 재시도 O. 인증, 429, 설정, 코드 오류 → 그대로 전달.
- `stop_after_attempt=2` = 최초 1 + 재시도 1. `Exception` 전체를 넣으면 비밀번호 오류도 재시도하게 된다.
- fallback은 모델을 **다시 부르지 않는** 준비된 안내 (`source_ids=[]`, `needs_human=true`).

## 5. 필수 5 — 스트리밍

```python
iterator = stream_chain.stream(prepared, config=config)        # invoke 아님!
yield {"type": "delta", "text": text}
answer = validate_sources(parsed, prepared["documents"])       # 필수 2 검수 재사용
yield {"type": "final", "reply": answer.model_dump(), "route": "primary"}
if not sent_delta and attempt == 0:                            # 자막 안 보냈고 첫 시도일 때만 재시도
yield {"type": "reset", "reason": "unverified_output"}
yield {"type": "final", "reply": support.safe_answer("fallback").model_dump(), "route": "fallback"}
```

- 조각은 `"policy-pyt"` + `"hon"`, `"fa"` + `"lse"`처럼 **단어 중간에서 끊긴다** → 각각 파싱하지 않고 모아서 한 번 검수.
- `model_dump()` = 객체를 dict로 Export. 괄호를 빼면 버튼을 누르지 않고 가리키기만 한 셈.

| 시나리오 | 출력 | 의미 |
|---|---|---|
| 기본 | delta 7 → final primary | 정상 |
| `temporary` | delta 7 → final primary | 시작 전 실패 → 조용히 재시도 (로그 스팸 8 → 10줄) |
| `midstream` | delta 1 → reset → final fallback | 도중 실패 → 재시도 없이 폐기 후 안내 |

## 6. 필수 5 — 실행 기록 (`TraceHandler`)

```python
state = {"started": self.clock(),
elapsed_ms = (self.clock() - state["started"]) * 1000          # 괄호 먼저, 초 → 밀리초
error_type = type(error).__name__ if error is not None else None
state["chunk_count"] = state["chunk_count"] + 1                # 킬 카운터 +1
```

- `type(error).__name__` = 고블린 #37(개체) → Goblin 설계도(`type`) → 이름표(`__name__`) → `"TemporaryModelError"`.
- `A if 조건 else B` = 게임 대사 분기. 바로 아래 줄 `'error' if error is not None else 'end'`와 같은 모양.
- 관측 메모: midstream에서 model 단계에서 청크 1개를 보낸 뒤 `TemporaryModelError`가 났고, 부모 run을 따라가면 같은 요청(request_summary)이다. 이미 delta를 보내 재시도하지 않고 reset 후 fallback으로 끝났다 (`model_attempts=1`, `route=fallback`).

| # | 함정 | 왜 틀렸나 | 올바른 방법 | 근거 |
|---|---|---|---|---|
| 1 | `document["doc_id"]` | `doc_id`는 `metadata` 안쪽에 있음 | `document.metadata["doc_id"]` (티켓 → 필드 → 이슈 키) | 1 |
| 2 | 점수에 필터 목록만 넣음 | 목록과 0은 크기 비교 불가 (`TypeError`) | `len([...])`로 건수 | 1 |
| 3 | parser 양식에 `support.QueryInput` | 그건 질문 접수 양식 | AI 답변 양식 `support.Answer` | 2 |
| 4 | `validate_sources(문서, 답변)` | 함수 칸 순서가 뒤바뀜 | `def` 줄의 순서대로 (답변, 문서) | 2 |
| 5 | `answer["source_ids"]` | `answer`는 객체 | 객체는 `.`(`answer.source_ids`), dict는 `[""]` | 2 |
| 6 | `todolen([...])` | `todo`를 덜 지움 (`NameError`) | `todo` 네 글자부터 드래그 | 🧭 5 |
| 7 | `with_retry(support.RECOVERABLE, 2, False)` | 이름표 필수 도구에 값만 넣음 (`TypeError`) | `옵션이름=값` | 4 |
| 8 | `stream_chain.invoke(...)` | 완성본 한 번 → 실시간 자막 불가 | `.stream(...)` | 5 |
| 9 | `yield yield {...}` | 남겨 둔 `yield` 뒤에 또 붙임 (`SyntaxError`) | 남긴 부분은 다시 쓰지 않기 | 5 |
| 10 | `{"started": self.clock()` 쉼표 누락 | 상자의 칸이 다음 줄로 이어짐 (`SyntaxError`) | 오류 메시지 "forgot a comma?" 읽기 | 6 |
| 11 | 이유 주석 "역할이 달라서 나뉜다" | 원인이 아니라 결과를 다시 말함 | 과제 문서의 힌트(의존성, 교체 가능성)로 쓰기 | 🧭 5 |
