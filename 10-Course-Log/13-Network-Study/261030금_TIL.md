## 💡 오늘의 학습 총평

- **오늘 나온 약어·용어 정리**

  | 약어·용어 | 풀스펠링 | 한 줄 뜻 |
  |---|---|---|
  | IP | Internet Protocol | 패킷에 출발지·목적지 주소를 붙이고 그 주소로 전달하게 하는 **통신 규약** (택배 송장 쓰는 규칙) |
  | IP 주소 | Internet Protocol Address | 네트워크에 연결된 **각 연결(인터페이스)** 을 구분하는 논리 주소 (송장의 받는 사람 주소) |
  | IPv4 / IPv6 | Internet Protocol version 4 / 6 | 32비트·10진수·점(.) / 128비트·16진수·콜론(:) |
  | 옥텟 | Octet | 비트 8개 묶음 (0~255). IPv4는 옥텟 4개 |
  | 듀얼 스택 | Dual Stack | IPv4와 IPv6를 함께 쓰는 방식 |
  | NAT | Network Address Translation (네트워크 주소 변환) | 사설 IP들을 공인 IP 하나로 바꿔 내보내는 기술 (IPv4를 아껴 쓴 비결) |
  | DHCP | Dynamic Host Configuration Protocol | IP 주소·서브넷 마스크·기본 게이트웨이·DNS 서버를 **자동으로** 나눠 주는 프로토콜 |
  | DORA | Discover · Offer · Request · Ack(nowledge) | DHCP 4단계: 찾기(방송) → 제안 → 요청 → 확정 |
  | 리스 타임 | Lease Time (임대 기간) | DHCP가 IP를 **빌려주는** 기간 (절반쯤 지나면 연장 요청) |
  | 세션 타임 | Session Timeout | 로그인·인증된 **접속을 유지**하는 시간 (끝나면 재인증) |
  | RADIUS | Remote Authentication Dial-In User Service | 네트워크 접속 인증 서버 프로토콜 (세션 타임 예시로 등장) |
  | DNS | Domain Name System | 이름(도메인)을 IP로 바꿔 주는 시스템 |
  | 호스트 | Host | 네트워크에 연결된 기기 |
  | 서브넷 / 서브넷팅 | Subnet / Subnetting | 네트워크를 더 작게 나눈 네트워크 / 나누는 작업 |
  | 브로드캐스트 | Broadcast | 같은 서브넷의 **모든 기기에게 한 번에** 보내는 통신 |
  | 서브넷 마스크 | Subnet Mask | 네트워크 부분은 1, 호스트 부분은 0으로 표시한 32비트 값 (주소 위에 대는 투명 자) |
  | CIDR | Classless Inter-Domain Routing | IP 뒤에 `/`와 마스크의 1 개수를 붙여 쓰는 표기 (`/24`) — 클래스 대신 크기를 자유롭게 |
  | 멀티캐스트 | Multicast | 여러 기기(그룹)에 한 번에 보내는 통신 (D클래스) |
  | 루프백 | Loopback | "나 자신" 주소 (IPv4 `127.0.0.1`, IPv6 `::1`) |
  | 기본 게이트웨이 | Default Gateway | 다른 네트워크로 가는 패킷을 전달하는 장치(보통 라우터)의 IP (단지 정문) |
  | IOS | Internetwork Operating System | 시스코 네트워크 장비의 운영체제 (DHCP lease 기본 1일 예시) |

- **핵심 통찰: 1회차의 "IP 주소"를 이번엔 "정의 → 비유 → 그림 → 같이 풀기" 순서로 제대로 잡았다**
  - 1회차가 "IP는 '어디로', MAC은 '이번 구간 누구에게'"라는 큰 그림이었다면, 오늘은 그 IP 주소 하나를 **규약 · 형식 · 할당 방식 · 나누는 법**까지 파고들었다.

    | Part | 오늘 배운 것 | 한 줄 정리 |
    |---|---|---|
    | 1 IP란? | IP(규약) ≠ IP 주소(번호), IP는 기기가 아니라 **연결마다** | 노트북을 와이파이 + 랜선에 연결하면 IP도 둘 |
    | 2 IPv4 vs IPv6 | 32비트 약 43억 개 vs 128비트 약 3.4 × 10³⁸개, 줄여 쓰기 규칙 | 사설 IP + NAT로 IPv4를 아껴 써서 지금은 **듀얼 스택** |
    | 3 고정 vs 유동 | DHCP 4단계(DORA), 리스 타임 ≠ 세션 타임 | 다른 기기가 **찾아와야** 하면 고정 IP |
    | 4 서브넷팅 기초 | 네트워크/호스트 부분, 2진수 변환, 서브넷 마스크, CIDR, 클래스 | "101동 1003호" — 경계는 마스크가 정함 |
    | 5 서브넷 계산 | 블록 크기 = 256 − 마스크 마지막 칸, 호스트 수 = 블록 − 2, 4단계 계산법 | 숫자가 가까워도 **다른 동**일 수 있음 |

- **두 번째 통찰: 서브넷 계산은 결국 "블록 크기" 하나로 풀린다**
  - 공식 두 개: **블록 크기 = 2^(호스트 비트 수) = 256 − 마스크 마지막 칸**(/24~/30), **호스트 수 = 블록 − 2**(네트워크 주소·브로드캐스트 주소는 기기에 못 줌).
  - 4단계: ① 블록 크기 → ② 0부터 블록씩 나누기 → ③ 주소가 들어간 블록 찾기 → ④ 첫 번째 = 네트워크, 마지막 = 브로드캐스트, 사이 = 쓸 수 있는 범위.
  - `/` 뒤 숫자가 1 커질 때마다 블록은 **절반**: 256 → 128 → 64 → 32 → 16 → 8 → 4.

- **세 번째 통찰: 클래스가 CIDR로 바뀐 이유 = "필요한 만큼만"**
  - 기기 300대가 필요한 회사: C클래스(/24)는 254대라 **부족**, B클래스(/16)는 65,534대라 6만 5천 개 넘게 **낭비** → CIDR `/23`이면 510대로 딱 맞다.
  - 지금 장비·클라우드는 모두 CIDR을 쓰지만, 클래스는 **기본 마스크와 사설 대역**을 이해하는 바탕이라 면접·자격증에 자주 나온다. 1회차의 사설 IP 대역 세 개(10.x / 172.16~31.x / 192.168.x)가 각각 A·B·C 클래스 안에 하나씩 있다.

- **향후 계획 및 다짐**
  - 2진수 변환과 4단계 계산은 **손으로 몇 번 더 풀기** — 해설집 Q5~Q8 복습 문제.
  - 면접 예상 질문 7개(Q1~Q7)는 **정의로 답하고, 비유로 떠올리는** 연습 (핵심 정리 PDF의 "초록=용어, 검정=정의, 갈색=비유" 읽는 법 그대로).
  - 공장 제어 쪽 진로를 생각하면, 오늘 나온 "**고정 IP를 기기에 직접 넣고 IP 관리대장으로 관리**", "**DHCP 범위 밖에서 번호 고르기**"가 현장에서 바로 마주칠 장면 같다. 제어 장비는 대부분 다른 기기가 찾아와야 하는 쪽이라 고정 IP가 많을 것 같아서, 서브넷 계산을 확실히 해 두고 싶다.
  - 다음 3회차: **OSI 7계층 · TCP/IP · 캡슐화**, 그리고 스위치·라우터 같은 장비가 몇 계층에서 일하는지.

## 🧭 종합 QA 체크포인트

> 아래 상세 내용 전체에 공통으로 적용되는 테스트·품질 관점을 먼저 모았다. 표의 **근거** 번호로 🎯 상세 내용을 찾아볼 수 있다.

### 1. "형식상 맞는 주소" ≠ "기기에 줄 수 있는 주소" ≠ "이 환경에서 써도 되는 주소"

| 검사 층 | 확인 | 예 | 근거 |
|---|---|---|---|
| ① 형식 | IPv4 숫자 4개, 각 0~255 | `256.1.1.1` → 둘 다 아님 | 2-5 |
| ② 의미 | 네트워크 주소·브로드캐스트 주소가 아닌가 | `192.168.10.64/26`은 형식은 맞지만 **네트워크 주소** | 5-1, 5-3 |
| ③ 예약 | 루프백·멀티캐스트·실험용이 아닌가 | `127.0.0.1`, `224.0.0.5` | 4-6 |
| ④ 환경 | DHCP 범위·다른 고정 IP와 겹치지 않나 | 공유기가 .100~.200을 나눠 주면 고정 IP는 .10~.50 | 3-4 |

- LLM 쪽에서 계속 나온 "형식 통과 ≠ 내용 통과"(RAG 3일차 JSON Schema, LLMOps 1장 completed ≠ 정답)가 IP 주소에서도 똑같이 성립한다. 입력 검증 기능을 테스트할 때 **층마다 따로** 케이스를 둬야 한다.

### 2. 겹치면 조용히 불안정해진다 — 충돌은 설계 단계에서 막는다

- 고정 IP를 DHCP 범위 안에서 고르면, 나중에 DHCP가 같은 번호를 다른 기기에 줄 수 있다 → **같은 IP를 가진 기기가 둘**, 통신이 불안정해진다. 에러 메시지가 바로 뜨는 게 아니라 "가끔 끊긴다"로 나타나는 **간헐 결함**이라 재현이 어렵다.
- 그래서 현장에서는 **IP 관리대장**으로 고정 IP를 기록한다. 게임 QA에서 테스트 서버·기기별 계정을 관리 시트로 배정해 겹치지 않게 하던 것과 같은 방식 — 충돌을 사후에 찾기보다 **배정 대장으로 사전에** 막는다.
- 고정 IP를 넣을 땐 **IP · 서브넷 마스크 · 기본 게이트웨이 · DNS** 네 가지를 함께. 하나라도 빠지면 "같은 동은 되는데 밖으로는 안 나감"(게이트웨이 누락), "IP로는 되는데 이름으로는 안 됨"(DNS 누락)처럼 **부분적으로만 실패**한다.

### 3. 비슷해 보이는 두 시간을 섞지 않는다 — 리스 타임 vs 세션 타임

| 구분 | 리스 타임 | 세션 타임 |
|---|---|---|
| 무엇의 시간 | **주소**를 빌리는 시간 | **접속**을 유지하는 시간 |
| 끝나 가면 / 끝나면 | 절반쯤 지나 연장 요청, 못 하면 반납 | 다시 로그인·재인증 |
| 예 | 시스코 IOS DHCP 풀 lease (기본 1일) | 무선 컨트롤러 Session Timeout, RADIUS, 웹 로그인 세션 |

- 세션이 끝나 재인증해도 **IP는 그대로일 수 있다.** 그래서 "와이파이 재로그인 후 접속이 안 된다"는 리포트를 받으면, IP가 바뀐 문제인지 인증만 풀린 문제인지 **원인 계층을 먼저 나눠야** 한다.
- CE 2-1의 "만료 ≠ 삭제", LLMOps 1장의 "flush ≠ 서버 조회"와 같은 원칙이다. 이름이 비슷한 두 상태가 **서로 다른 시계·다른 계층**에서 돌아간다.

### 4. 계산 결과는 "정식 방법"과 "빠른 방법" 두 개로 교차 검증한다

- 블록 크기: 정식 `2^(32 − 26) = 64` = 빠른 `256 − 192 = 64`. 2진수: 2로 나눠 구한 `11001000`을 **자릿값 더하기**(128 + 64 + 8 = 200)로 거꾸로 확인.
- 빠른 방법(`256 − 마지막 칸`)은 **/24~/30에서만** 쓸 수 있다는 적용 범위가 있다. /23처럼 셋째 칸까지 걸치면 정식 방법(2^호스트 비트)으로 가야 한다 — 지름길에는 **전제 조건**이 있다.
- QA에서 기대 결과를 두 가지 독립된 방법으로 계산해 맞춰 보는 **교차 검증(오라클 2개)** 과 같다. 오늘 Claude가 교안 정답을 `ipaddress` 모듈로 다시 계산한 것도 같은 맥락.

### 5. "언제 고정, 언제 유동"의 기준은 하나 — 다른 기기가 나를 찾아와야 하나?

| 기기 · 회선 | 보통 | 이유 |
|---|---|---|
| 노트북 · 휴대폰 | 유동 | 내가 찾아가는 쪽, 어디서든 자동 |
| 웹 서버 · DB 서버 · 사무실 프린터 | 고정 | 다른 기기가 늘 같은 주소로 찾아와야 |
| 집 인터넷 회선 | 유동 | 통신사 가정용 기본 |
| 회사 서버용 회선 | 고정 | 통신사에 따로 신청 (보통 추가 비용) |

- 1회차 Claude 포인트(테스트 코드에 동기 IP를 하드코딩하면 다음 날 깨진다)의 근거가 오늘 정식으로 나왔다 — **유동 IP는 리스 기간이 끝나거나 재접속하면 바뀔 수 있다.** 사내 Ollama·vLLM 서버처럼 여러 사람이 찾아오는 모델 서버는 고정 IP나 도메인으로.
- 고정/유동 구분은 **공인 IP에도, 사설 IP에도** 다 있다 (서로 다른 축).

### 6. Claude가 짚어준 확인 포인트

**① IP 주소 입력 검증은 ISTQB의 경계값 분석·동등 분할 연습 문제로 딱 맞다**
- 오늘 "같이 풀어 봐요 ①"(256.1.1.1)과 "네트워크·브로드캐스트 주소는 기기에 못 준다"를 합치면, IP 입력 칸 하나에 대한 테스트 설계가 나온다. Claude가 파이썬 `ipaddress` 모듈로 실제 판정을 돌려 봤다:

  | 입력 | 분할 · 경계 | `ipaddress` 판정 | 기기에 줄 수 있나 |
  |---|---|---|---|
  | `0.0.0.0` | 하한 경계 | 유효한 주소 | ✗ (특수 주소) |
  | `255.255.255.255` | 상한 경계 | 유효한 주소 | ✗ (전체 브로드캐스트) |
  | `256.1.1.1` | 상한 + 1 | **오류** | — |
  | `-1.0.0.0` | 하한 − 1 | **오류** | — |
  | `192.168.0` | 숫자 3개 (형식 분할) | **오류** | — |
  | `192.168.0.1 ` | 뒤에 공백 | **오류** | — |
  | `192.168.010.1` | 0으로 시작하는 옥텟 | **오류** | — |
  | `192.168.10.64` (/26) | 블록 첫 주소 | 유효한 주소 | ✗ (**네트워크 주소**) |
  | `192.168.10.65` (/26) | 블록 첫 주소 + 1 | 유효한 주소 | ✓ |
  | `192.168.10.127` (/26) | 블록 마지막 주소 | 유효한 주소 | ✗ (**브로드캐스트**) |

- 눈여겨볼 건 `192.168.010.1`이다. 파이썬은 거절하지만, 일부 오래된 구현은 0으로 시작하는 숫자를 **8진수**로 읽어서 `010`을 **8**로 해석하기도 한다. 같은 문자열을 시스템마다 다르게 읽을 수 있으니, 여러 구성 요소가 IP 문자열을 주고받는 곳에서는 **같은 입력에 대한 해석이 일치하는지**도 테스트 항목이 된다.
- 그리고 표의 마지막 세 줄처럼 **경계는 고정값(0, 255)만이 아니라 서브넷마다 움직인다.** /26이면 .64·.127이 경계, /28이면 .0·.15·.16·.31…이 경계다. 경계값 분석을 할 때 "경계가 어디서 정해지는가(마스크)"를 먼저 알아야 한다는 점에서, ISTQB CTFL의 BVA(Boundary Value Analysis, 경계값 분석) 개념을 실제 도메인에 적용해 볼 좋은 예제다.

**② 서브넷 쪼개기는 "남는 것"까지 같이 봐야 한다 — 크기는 2의 거듭제곱으로만 나온다**
- Q3 "30명 팀 → /27(30대)"은 정확히 맞아떨어지는 경우다. 한 명만 늘어 31명이 되면 /27(30대)로는 부족해 **/26(62대)** 으로 가야 하고, 31대가 남는다. 클래스의 낭비 문제를 CIDR이 줄였지만, CIDR도 블록이 **2의 거듭제곱**이라 경계를 넘는 순간 크기가 두 배로 뛴다.
- 그래서 실제 배정은 "지금 몇 대"가 아니라 **앞으로 늘어날 대수까지** 보고 정한다. 300대 회사에 /23(510대)을 주는 오늘 예시도, 지금 딱 300대라면 210대의 여유를 둔 셈이다.
- QA 관점에서는 **용량 경계 테스트**와 같다. 서브넷의 마지막 호스트(30번째)까지는 정상이고, 31번째 기기는 주소를 못 받는다 — DHCP 풀이 바닥났을 때 새 기기가 어떤 증상을 보이는지(주소를 못 받음 → 자동 사설 주소로 떨어짐 등)가 확인 항목이 된다.

**③ 1회차 "같은 와이파이인데 왜 안 될까?"를 이제 계산으로 좁힐 수 있다**
- 1회차에서 `OLLAMA_HOST=0.0.0.0`으로 열어도 동기 접속이 실패할 수 있는 이유로 "공용 와이파이의 기기 간 차단"을 짚었다. 오늘 배운 서브넷으로 확인할 게 하나 더 생겼다 — **두 기기가 정말 같은 동(서브넷)에 있나?**
- 오늘 예시처럼 `192.168.1.50/26`과 `192.168.1.70/26`은 숫자가 20밖에 차이 나지 않는데 **다른 동**(0~63 / 64~127)이다. Q4의 `.10/28`과 `.20/28`도 다른 동이다. 다른 동이면 직접 통신하지 않고 **게이트웨이(정문)를 거쳐야** 하고, 그 사이 장비 설정에 따라 막힐 수 있다.
- 그래서 "같은 건물·같은 와이파이 이름인데 접속이 안 된다"를 볼 때 확인 순서가 하나 늘어난다: ① 서버가 켜져 있나 → ② 서버가 모든 주소로 받나(`0.0.0.0`) → ③ **두 기기의 IP와 마스크로 네트워크 주소가 같은지 계산** → ④ 기기 간 차단·방화벽. 1회차의 구간별 확인 표에 ③이 들어간다.

## Part 1. IP란?

### 1-1 : IP (Internet Protocol)
- **핵심 개념**:
  - **정의**: 네트워크 계층에서 데이터 조각(패킷)에 **출발지와 목적지 주소**를 붙이고, 그 주소를 보고 목적지까지 전달하게 하는 **통신 규약.**
  - **비유**: 택배를 보낼 때 송장을 쓰고, 송장의 주소를 보고 배달하는 규칙.
  - 그림: 패킷 = 출발지 IP(`192.168.0.23`) + 목적지 IP(`203.0.113.7`) + 데이터("안녕하세요"). **라우터는 목적지 IP를 보고 다음 길을 정한다.** 네트워크 계층은 3회차 OSI 7계층에서 자세히.
- **QA 체크포인트**:
  - "IP"와 "IP 주소"는 **다른 것** — 규약과 그 규약에서 쓰는 번호. 용어를 섞어 쓰면 커뮤니케이션 결함이 생긴다 (면접 Q1).

### 1-2 : IP 주소
- **핵심 개념**:
  - **정의**: IP 통신에서 네트워크에 연결된 **각 연결(인터페이스)** 을 구분하고 위치를 나타내는 논리 주소. **같은 네트워크 안에서는 겹치면 안 된다.**
  - **비유**: 송장의 받는 사람 주소. 집마다 주소가 달라야 배달된다.
  - IP는 기기가 아니라 **연결마다** 붙는다 — 노트북 하나를 와이파이(`192.168.0.23`)와 랜선(`192.168.0.40`)에 동시에 연결하면 **IP가 둘.**
- **QA 체크포인트**:
  - "기기 하나 = IP 하나"라는 가정은 틀릴 수 있다. 기기별 접속 로그·통계를 IP로 집계하면 **연결이 여러 개인 기기가 여러 대로** 잡힐 수 있다 (1회차의 "무작위 MAC으로 같은 기기가 여러 대로 잡힘"과 같은 유형).

## Part 2. IPv4와 IPv6

### 2-1 : IPv4
- **핵심 개념**:
  - **정의**: 32비트 길이의 IP 주소 체계. 8비트씩 4덩어리(**옥텟**)를 0~255의 10진수로 쓰고 점(.)으로 구분. 지금 가장 많이 쓰는 방식.
  - **비유**: 자릿수가 정해진 전화번호. 쓰는 사람이 늘면서 번호가 모자라기 시작했다.
  - 8비트 × 4 = 32비트 → 2³² = **약 43억 개.**

### 2-2 : IPv6
- **핵심 개념**:
  - **정의**: 128비트 길이의 IP 주소 체계. 16비트씩 8묶음을 **16진수**(0~9, a~f)로 쓰고 콜론(:)으로 구분. IPv4 주소 부족을 해결하려고 만든 다음 버전.
  - **비유**: 번호가 모자라 자릿수를 크게 늘린 새 전화번호 체계.
  - 16비트 × 8 = 128비트 → 2¹²⁸ = **약 3.4 × 10³⁸개.** 나 자신은 `::1`. `2001:db8`로 시작하는 주소는 **교재용 예시 주소.**

### 2-3 : IPv6 줄여 쓰는 규칙 2가지
- **핵심 개념**:
  - 원래: `2001:0db8:0000:0000:0000:ff00:0042:8329`
  - 규칙 ① **묶음 앞의 0은 생략** → `2001:db8:0:0:0:ff00:42:8329`
  - 규칙 ② **연속된 0 묶음은 `::`로** → `2001:db8::ff00:42:8329`
  - **`::`는 한 주소에 딱 한 번만** — 두 번 쓰면 각각 몇 묶음이 0인지 알 수 없다. 0 묶음이 여러 군데면 **더 긴 쪽**(길이가 같으면 **앞쪽**)을 줄인다.
- **QA 체크포인트**:
  - **같은 주소, 여러 표기** — 원래 표기와 줄인 표기는 같은 주소다. 문자열로 비교하면 "다른 주소"로 판정하는 결함이 생긴다. 비교 전 **정규화(같은 형태로 맞추기)** 가 필요하다 (LLMOps 1-2의 `type.upper()` 같은 정규화와 같은 이유).
  - **모호성 금지 규칙**(`::` 한 번만)은 해석이 하나로 정해지게 만드는 설계 — 입력 형식 명세가 모호하면 구현마다 다르게 읽는다.

### 2-4 : IPv4 vs IPv6 한눈에
- **핵심 개념**:

  |  | IPv4 | IPv6 |
  |---|---|---|
  | 길이 | 32비트 | 128비트 |
  | 개수 | 약 43억 개 | 약 3.4 × 10³⁸개 |
  | 표기 | 10진수 4덩어리, 점(.) | 16진수 8묶음, 콜론(:) |
  | 예시 | `192.168.0.10` | `2001:db8::ff00:42:8329` |
  | 나 자신 | `127.0.0.1` | `::1` |

  - IPv6가 있는데 왜 아직 IPv4를 많이 쓸까? → **사설 IP + NAT**(사설 IP를 공인 IP 하나로 바꿔 내보냄)로 아껴 썼기 때문. 집에 기기가 열 대여도 공인 IP는 하나면 된다. 그래서 지금은 **듀얼 스택.**

### 2-5 : 같이 풀어 봐요 ①② (교안 정답, Claude가 `ipaddress`로 다시 계산해 일치 확인)
- **① IPv4? IPv6?**: `10.0.0.1` IPv4 · `fe80::1` IPv6 · `172.16.5.200` IPv4 · `2001:db8::ff00:42:8329` IPv6 · `256.1.1.1` **둘 다 아님**(256은 IPv4에 없음).
- **② IPv6 줄여 쓰기**:
  | 원래 | 정답 |
  |---|---|
  | `2001:0db8:0000:0000:0000:0000:0000:0001` | `2001:db8::1` |
  | `fe80:0000:0000:0000:0204:61ff:fe9d:f156` | `fe80::204:61ff:fe9d:f156` |
  | `2001:db8:0:0:1:0:0:1` | `2001:db8::1:0:0:1` (0 묶음 길이가 같아 **앞쪽만**) |
- **QA 체크포인트**:
  - `256.1.1.1`은 전형적인 **상한 + 1** 경계값 케이스 (🧭 6-①).

## Part 3. 고정 IP와 유동 IP

### 3-1 : 유동 IP (동적 IP)
- **핵심 개념**:
  - **정의**: **DHCP 서버**가 정해진 기간(**임대 기간, Lease Time**) 동안 기기에 자동으로 빌려주는 IP. 기간이 끝나거나 다시 접속하면 다른 주소를 받을 수 있다.
  - **비유**: 도서관 열람실 좌석. 올 때마다 빈자리를 배정받는다.
  - 같은 노트북: 월 `.23` → 화 `.23` → 수 `.31`. **매번 바뀌는 건 아니지만, 바뀔 수 있다는 게 핵심.**

### 3-2 : DHCP — IP를 나눠 주는 4단계
- **핵심 개념**:
  - **정의**: 기기에 **IP 주소 · 서브넷 마스크 · 기본 게이트웨이 · DNS 서버**를 자동으로 나눠 주는 프로토콜.
  - **비유**: 열람실 좌석 배정 데스크. 자리와 이용 시간을 정해 준다.
  - **DORA**: ① **Discover** "주소 줄 분 있나요?"(**방송** — 아직 주소가 없으니) → ② **Offer** "192.168.0.23 어때요?" → ③ **Request** "그 주소 쓸게요" → ④ **Ack** "확정! 임대 기간 동안 쓰세요."
  - 임대 기간의 **절반쯤** 지나면 노트북이 연장을 요청하고, 안 쓰면 반납.
- **QA 체크포인트**:
  - DHCP 1단계의 "방송"이 후반전의 **브로드캐스트**다 — 서브넷을 나누면 이 방송도 그 서브넷 안에서만 울린다.

### 3-3 : 리스 타임 vs 세션 타임
- **핵심 개념**: 🧭 3 표 참고. 한 줄 구분 — **리스 타임은 "주소"를 빌리는 시간, 세션 타임은 "접속"을 유지하는 시간.** 세션이 끝나도 IP는 그대로일 수 있다. 시스코 IOS DHCP 풀의 lease 기본값은 1일.
- **QA 체크포인트**:
  - 증상("재로그인 후 안 됨")이 같아도 원인 계층(주소 vs 인증)이 다를 수 있다 → 재현 조건에 **"IP가 바뀌었는지"** 를 같이 기록.

### 3-4 : 고정 IP (정적 IP)와 어디에 무엇을 쓸까
- **핵심 개념**:
  - **정의**: 관리자가 기기에 직접 설정하거나, 통신사가 계속 같은 주소로 할당해 주는 IP. 바뀌지 않아서 다른 기기가 늘 같은 주소로 찾아올 수 있다.
  - **비유**: 우리 집 주소. 친구가 언제 찾아와도 같은 곳.
  - 어디에 무엇을: 🧭 5 표 참고. 현장에서는 **고정 IP를 기기에 직접 넣고 IP 관리대장에 적어서** 겹치지 않게 관리.
  - **고정 IP를 넣을 땐 4가지 함께**: IP 주소(나의 주소) · 서브넷 마스크(어디까지가 우리 동인지) · 기본 게이트웨이(밖으로 나가는 문) · DNS 서버(이름을 IP로 바꿔 주는 곳). 유동 IP는 DHCP가 한 번에 준다.
  - **충돌 주의**: 고정 IP는 **DHCP가 나눠 주는 범위 밖**의 번호로. 공유기가 .100~.200을 나눠 준다면 고정 IP는 .10~.50. 겹치면 같은 IP 기기가 둘 → 통신 불안정.
- **같이 풀어 봐요 ③** (교안 정답): 노트북 **유동** · 회사 웹 서버 **고정** · 사무실 프린터 **고정** · 휴대폰 **유동** · 팀 DB 서버 **고정.** 기준은 하나 — **다른 기기가 이 기기를 찾아와야 하나?**
- **QA 체크포인트**:
  - **설정 누락의 부분 실패** — 네 값 중 하나만 빠져도 "일부만 안 됨"으로 나타난다 (🧭 2).
  - **배정 대장으로 충돌 예방** — 사후 탐지보다 사전 관리.

## Part 4. 서브넷팅 기초

### 4-1 : 네트워크 부분과 호스트 부분
- **핵심 개념**:
  - **정의**: IP 주소의 **앞쪽 비트는 어느 네트워크인지**(네트워크 부분), **뒤쪽 비트는 그 네트워크 안의 어느 기기인지**(호스트 부분). 경계는 **서브넷 마스크**가 정한다.
  - **비유**: 아파트 주소 "101동 1003호" — 101동은 네트워크, 1003호는 호스트.
  - `192.168.0.10`(/24 기준): `192.168.0` = 동, `10` = 호수. **같은 동끼리는 바로 통하고, 다른 동은 단지 정문(게이트웨이)을 거친다.**

### 4-2 : 서브넷 · 서브넷팅 · 브로드캐스트
- **핵심 개념**:
  - **정의**: 서브넷 = 하나의 네트워크를 더 작게 나눈 네트워크 / 서브넷팅 = 나누는 작업 / 브로드캐스트 = 같은 서브넷의 모든 기기에게 한 번에 보내는 통신.
  - **비유**: 큰 단지를 동으로 나누면, 안내 방송이 그 동에만 울린다.
  - 나누는 이유: **방송 줄이기, 관리와 보안, 주소 아끼기.**

### 4-3 : 비트 · 옥텟 · 2진수와 10진수
- **핵심 개념**:
  - **정의**: 비트 = 0 또는 1을 담는 가장 작은 단위 / 옥텟 = 비트 8개 묶음(0~255).
  - **비유**: 전구 하나가 비트, 전구 8개짜리 줄이 옥텟. 전구마다 값 128 · 64 · 32 · 16 · 8 · 4 · 2 · 1, **켜진 전구 값을 더한다.** 다 켜면 255, 다 끄면 0 → 그래서 IPv4 숫자는 0~255.
  - 10진수는 자릿값이 10의 제곱(352 = 3×100 + 5×10 + 2×1), 2진수는 **2의 제곱**(1011 = 2³ + 2¹ + 2⁰ = 11). 비유: 1·2·4…128원짜리 동전이 한 개씩, 내면 1, 안 내면 0.
  - **10진수 → 2진수**: 몫이 0이 될 때까지 2로 나누고 **나머지를 아래에서 위로** — 200 = `11001000`. 확인은 2⁷ + 2⁶ + 2³ = 128 + 64 + 8 = 200. 8자리가 안 되면 앞에 0 (10 → `00001010`).
  - **2진수 → 10진수**: 비트 위에 자릿값을 적고 **1인 자리만 더하기** — `10101000` = 128 + 32 + 8 = 168.
  - 서브넷 마스크에 자주 나오는 값: `11000000` = 192 · `11100000` = 224 · `11110000` = 240.
- **같이 풀어 봐요 ④** (교안 정답, Claude가 계산해 확인): 200 → `11001000` · `11110000` → 240 · `10101010` → 170 · 255 → `11111111` · 64 → `01000000`.
- **QA 체크포인트**:
  - **역변환으로 검증** — 2로 나눠 구한 값을 자릿값 더하기로 되돌려 맞춰 본다 (🧭 4).

### 4-4 : 서브넷 마스크와 CIDR 표기
- **핵심 개념**:
  - **서브넷 마스크 정의**: IP 주소에서 **네트워크 부분은 1, 호스트 부분은 0**으로 표시한 32비트 값. 동에 해당하는 전구는 켜고 호수 전구는 끈 것 → 10진수로 255나 0. **비유**: 주소 위에 대는 투명 자.
  - `192.168.0.10` + `255.255.255.0` → 앞 세 칸이 동, 마지막 칸이 호수.
  - **CIDR 정의**: IP 뒤에 `/`와 네트워크 부분의 비트 수(마스크의 1 개수)를 붙여 쓰는 표기법(`192.168.0.10/24`). **비유**: "앞 24칸이 동이에요"라고 줄여 말하기.
  - `255.255.255.0` = 켜진 전구 24개 = `/24`. `/16` = `255.255.0.0`. `/26` = `255.255.255.192` (192 = `11000000`, 전구 2개 더 → 24 + 2).
- **같이 풀어 봐요 ⑤** (교안 정답): `/25` → `255.255.255.128` · `255.255.255.240` → `/28`(24 + 4) · `/16` → `255.255.0.0` · `255.255.255.0` → `/24`.

### 4-5 : IP 주소 클래스와 그 한계
- **핵심 개념**:
  - **정의**: 초기 IPv4에서 첫 번째 숫자(앞쪽 비트)로 주소를 A~E 다섯 등급으로 나눈 방식. 등급마다 네트워크 부분 크기가 정해져 있었다. **비유**: 옛날 아파트 분양 평수(대·중·소형으로만).

    | 클래스 | 첫 번째 숫자 | 기본 마스크 | 용도 | 사설 대역 |
    |---|---|---|---|---|
    | A | 1 ~ 126 | /8 | 대규모 | `10.0.0.0/8` |
    | B | 128 ~ 191 | /16 | 중규모 | `172.16.0.0/12` |
    | C | 192 ~ 223 | /24 | 소규모 | `192.168.0.0/16` |
    | D | 224 ~ 239 | 없음 | 멀티캐스트 | – |
    | E | 240 ~ 255 | 없음 | 실험용(예약) | – |

    127은 A 범위지만 **루프백 전용**이라 빠지고, 0도 예약.
  - **한계 → CIDR**: 300대 회사 — C(/24) 254대 부족, B(/16) 65,534대 낭비, CIDR **/23 510대** (Claude가 계산해 확인: 2⁹ − 2 = 510).
- **같이 풀어 봐요 ⑥** (교안 정답): `10.1.2.3` A · `172.16.5.200` B · `192.168.0.10` C · `224.0.0.5` D(멀티캐스트) · `127.0.0.1` 루프백(A 범위지만 예약).
- **QA 체크포인트**:
  - **고정 크기 설계의 낭비** — 선택지가 세 개뿐이면 실제 요구와 안 맞는다. CIDR도 2의 거듭제곱이라 경계에서 두 배로 뛴다 (🧭 6-②).

## Part 5. 서브넷 계산

### 5-1 : 네트워크 주소와 브로드캐스트 주소
- **핵심 개념**:
  - **정의**: 네트워크 주소 = 호스트 부분이 **모두 0**인 주소(서브넷 자체) / 브로드캐스트 주소 = 호스트 부분이 **모두 1**인 주소(서브넷 전체에 보낼 때). **둘 다 기기에 줄 수 없다.**
  - **비유**: 동 이름표(○○동)와 동 전체 안내 스피커. 집 주소로는 못 쓴다.
  - `192.168.0.0/24`: `.0` 네트워크 주소 / `.1 ~ .254` 기기 몫 / `.255` 브로드캐스트 → **256 − 2 = 254대** (면접 단골).
- **같이 풀어 봐요 ⑦** (교안 정답): `192.168.1.0/24` → 네트워크 `192.168.1.0` · 브로드캐스트 `192.168.1.255` · 범위 `.1 ~ .254` · 254대.

### 5-2 : 블록 크기와 호스트 수, 치트시트
- **핵심 개념**:
  - **정의**: 블록 크기 = 서브넷 하나의 주소 개수 = **2^(호스트 비트 수)** / 호스트 수 = **블록 크기 − 2.**
  - **비유**: 한 동의 칸 수에서 이름표와 스피커 자리 2칸을 뺀 것.
  - `/26`: 정식 `32 − 26 = 6 → 2⁶ = 64` = 빠른 `256 − 192 = 64` → 호스트 62대.

    | 표기 | 서브넷 마스크 | 블록 | 호스트 |
    |---|---|---|---|
    | /24 | 255.255.255.0 | 256 | 254 |
    | /25 | 255.255.255.128 | 128 | 126 |
    | /26 | 255.255.255.192 | 64 | 62 |
    | /27 | 255.255.255.224 | 32 | 30 |
    | /28 | 255.255.255.240 | 16 | 14 |
    | /29 | 255.255.255.248 | 8 | 6 |
    | /30 | 255.255.255.252 | 4 | 2 |

    `/` 뒤 숫자가 1 커질 때마다 블록은 **절반.**
- **같이 풀어 봐요 ⑧** (교안 정답): `/27` 256 − 224 = 32 → 30 · `/29` 8 → 6 · `/25` 128 → 126 · `/28` 16 → 14.

### 5-3 : 4단계 계산법 — `192.168.10.77/26`
- **핵심 개념**:
  1. **블록 크기**: /26 → 마스크 `255.255.255.192` → 256 − 192 = **64**
  2. **64씩 나누기** (항상 0부터): 0~63 · 64~127 · 128~191 · 192~255
  3. **77이 들어간 블록**: 64~127
  4. **답 읽기**: 네트워크 `192.168.10.64`(블록 첫 번째) · 브로드캐스트 `192.168.10.127`(블록 마지막) · 범위 `.65 ~ .126` · **62대**
  - 이 4단계면 /24~/30 주소는 다 풀 수 있다.

### 5-4 : 쪼개기 — `192.168.1.0/24`를 4팀으로
- **핵심 개념**:
  - 256 ÷ 4 = 64 → 블록 64 = **/26.**

    | 팀 | 서브넷 | 쓸 수 있는 범위 | 대수 |
    |---|---|---|---|
    | 1팀 | `192.168.1.0/26` | .1 ~ .62 | 62 |
    | 2팀 | `192.168.1.64/26` | .65 ~ .126 | 62 |
    | 3팀 | `192.168.1.128/26` | .129 ~ .190 | 62 |
    | 4팀 | `192.168.1.192/26` | .193 ~ .254 | 62 |

  - 팀마다 서브넷이 따로 생겨 **한 팀의 방송이 다른 팀에 울리지 않는다.**
- **QA 체크포인트**:
  - 나눈 뒤 쓸 수 있는 대수는 254 → 62 × 4 = **248**로 줄어든다(서브넷마다 2개씩 빠지므로). 나누는 데도 **비용**이 있다 — Claude가 계산해 확인.

### 5-5 : 기본 게이트웨이 — 같은 동일까?
- **핵심 개념**:
  - **정의**: 다른 네트워크로 가는 패킷을 받아 전달해 주는 장치(보통 라우터)의 IP 주소. 보통 그 서브넷의 **첫 번째 주소**를 많이 쓴다(**관례**일 뿐 필수 아님).
  - **비유**: 아파트 단지 정문. 다른 동이나 바깥에 가려면 정문을 지난다.
  - `192.168.1.50/26`과 `192.168.1.70/26` → 블록 64로 나누면 50은 0~63, 70은 64~127 → **숫자는 가까워도 다른 동** → 게이트웨이를 거쳐 통신.
- **QA 체크포인트**:
  - **"관례"와 "규칙"을 구분** — 게이트웨이가 첫 주소라는 건 관례라서, 이를 가정한 자동화 스크립트는 다른 환경에서 깨질 수 있다.

### 5-6 : 연습 문제 (교안 정답, Claude가 `ipaddress`로 다시 계산해 일치 확인)

| 문제 | 블록 | 네트워크 | 브로드캐스트 | 범위 | 대수 |
|---|---|---|---|---|---|
| Q1 `10.0.0.130/25` | 128 (128~255) | `10.0.0.128` | `10.0.0.255` | .129 ~ .254 | 126 |
| Q2 `172.16.5.200/27` | 32 (192~223) | `172.16.5.192` | `172.16.5.223` | .193 ~ .222 | 30 |

- **Q3** 30명 팀 → **/27**(30대). /28은 14대라 부족.
- **Q4** `192.168.0.10/28`과 `192.168.0.20/28` → 블록 16, 10은 0~15, 20은 16~31 → **다른 동.**

- **오늘의 한 잔 요약**: ① IP와 IP 주소 — 규약과 번호 ② IPv4와 IPv6 — 32비트 약 43억 vs 128비트, 지금은 함께 ③ 고정과 유동 — 늘 같은 주소(서버) vs DHCP가 빌려줘서 바뀔 수 있는 주소 ④ 서브넷 계산 — **블록 = 256 − 마스크 마지막 칸, 호스트 = 블록 − 2.**
