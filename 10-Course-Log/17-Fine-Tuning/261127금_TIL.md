## 💡 오늘의 학습 총평

- **오늘 나온 약어·용어 정리**

  | 약어·용어 | 풀스펠링 | 한 줄 뜻 |
  |---|---|---|
  | 인계 | handoff (핸드오프) | 모델을 **근거와 함께** 다음 사람에게 넘기는 일. 사용 승인과는 별개 |
  | 동결 | freeze | test를 열기 **전에** 후보 · 설정 · 평가 기준을 기록해 두는 절차. 파일을 잠그는 기능이 아님 |
  | 동결 기록 | frozen manifest (프로즌 매니페스트) | 어떤 파일과 조건을 묶었는지 적은 목록(`frozen_manifest.json`) |
  | 개봉 기록 | holdout access record (홀드아웃 접근 기록) | test를 **언제 열었는지** 남기는 별도 파일(`holdout_access.json`) |
  | holdout | holdout (홀드아웃, 남겨 둔 자료) | 후보 선택에 쓰지 않고 마지막에 한 번만 보는 test |
  | 모델 카드 | model card (모델 카드) | 용도 · 출처 · 결과 · 한계 · 재현 조건을 적은 모델 설명서(`MODEL_CARD.md`) |
  | 인계 번들 | handoff bundle (핸드오프 번들) | 추론 모델 + 기록 + 보고서 + 카드를 묶은 ZIP. 학습을 재개하는 체크포인트가 아님 |
  | SHA-256 | Secure Hash Algorithm 256-bit (보안 해시) | 파일 내용의 지문. **같은 바이트인지**만 알려 줌 |
  | 포장 해시 · 내용 해시 | package hash · content hash | ZIP 통째의 지문 / ZIP 안의 파일 각각의 지문. 둘 다 남김 |
  | 설정 해시 | canonical JSON hash (정규화 JSON 해시) | 키 순서 · 공백은 무시하고 **값**만 반영한 설정의 지문 |
  | format_ok · status_match · reference_exact | format ok · status match · reference exact match | 출력 계약을 지켰나 / 답함 · 보류가 맞나 / 모범답안 객체와 완전히 같나 |
  | 로짓 | logits (로짓) | 다음 토큰 후보별 점수. 복원 확인에서 `torch.equal`로 값이 **정확히** 같은지 봄 |
  | HF | Hugging Face (허깅페이스) | 모델 공유 플랫폼. 보강에서 비공개 저장소 · Endpoint 업로드를 다룸 |
  | Endpoint | inference endpoint (추론 엔드포인트) | 모델을 서버로 띄워 요청을 받게 한 것. 유료이므로 시연 후 삭제 |
  | BF16 · L4 | Brain Floating Point 16-bit · NVIDIA L4 GPU | 후보의 저장 · 계산 정밀도 / 이번 실행 GPU |

- **핵심 통찰: 8장은 학습하지 않고, 확인하고 넘긴다 — 후보 고정 → 한 번 개봉 → 근거째 인계**
  - 8-1 용도와 한계를 정하고 7장 기록이 지금 파일을 가리키는지 확인 → 8-2 test를 열기 전에 동결 기록을 남김 → 8-3 test를 **한 번** 열어 최종 평가하고 번들에서 복원 → 8-4 주장마다 근거와 조건을 붙여 인계.
  - 마지막에 배운 방법(DPO)이 후보가 아니다. 후보는 7장에서 dev로 고른 **full_sft**이고, `deployment_ready: False` · `test_used: False`는 평가 후보일 뿐 배포 승인이 아니라는 표시다.

- **두 번째 통찰: test는 한 번만 열고, 결과를 보기 전에 규칙을 적어 둔다**
  - 동결 기록에 모델 파일 6개의 지문 · 정밀도 · 생성 설정 · 대화 틀 지문 · **평가 규칙**(성공 기준과 분모 12) · 복원 표본 선택 규칙까지 넣고, 이미 있으면 덮어쓰지 않고 멈춘다. test를 열 때는 `holdout_access.json`을 **다른 파일에** 쓰고, 이미 있으면 다시 열지 않는다.
  - 동결과 개봉을 한 파일에 섞으면 동결 파일을 고칠 때 지문이 바뀌어 “언제 무엇을 정했나”가 흐려진다. 게임 QA로 바꾸면 **테스트 계획서(합격 기준)를 승인받은 뒤에 테스트를 돌리고, 결과를 보고 합격 기준을 바꾸지 않는 것**과 같다.

- **세 번째 통찰: 새 데이터(test)에서도 같은 약점이 그대로 나왔다 — 형식 12/12, 완전 일치 10/12**

  | 지표 | baseline | full_sft |
  |---|---|---|
  | JSON 객체 | 0/12 | 12/12 |
  | 형식 통과 (`format_ok`) | 0/12 | 12/12 |
  | status 일치 | 0/12 | 12/12 |
  | 참조 완전 일치 | 0/12 | **10/12** |

  - 틀린 두 문항은 모두 **over_limit**(policy02: 80,000원 > 75,000원, policy11: 115,000원 > 110,000원)이고, 둘 다 “한도 이하이므로 사전 승인이 필요하지 않습니다”라고 답했다. 형식 · status는 맞는데 **승인 판단은 반대**다. dev에서 본 약점(초과 금액 오답)이 새 그룹에서도 재현됐다.
  - base의 0/12는 업무 오답이 아니라 **형식 계약의 0**이다(코드 펜스 9 · `answered` 한 단어 2 · 설명문이 192토큰에서 잘림 1). SFT가 바꾼 것은 펜스 없는 JSON 한 줄, 근거가 없으면 abstained다.
  - 세 지표(format_ok · status_match · reference_exact)는 **하나의 정답률로 합치지 않는다.** 분모는 JSON이 깨진 답도 포함한 모델별 12문항이다.

- **네 번째 통찰: 근거마다 말할 수 있는 것이 다르다 — 인계 ≠ 사용 승인**

  | 확인한 근거 | 말할 수 있는 것 | 자동으로 따라오지 않는 결론 |
  |---|---|---|
  | SHA-256 일치 | 기록과 보관 파일의 바이트가 같다 | 내용의 진위 · 업무 정답 |
  | 복원 원문 · 로짓 일치 | 그 환경 · 그 입력에서 실행이 같다 | 모든 장치 · 모든 질문의 같은 결과 |
  | JSON 형식 통과 | 정해 둔 출력 계약을 지켰다 | 금액 비교 · 현재 규정 적용의 정답 |
  | 원문의 사람 검토 | 검토한 문항의 판단이 타당하다 | 검토 안 한 질문의 일반 정확도 |

  - 인계 번들은 **17개 파일, 0.932GiB**(추론 모델 6개 + 동결 · 개봉 기록 + 최종 보고서 + 모델 카드 + 7장 두 기록 + 3장 보고서 + 데이터 ZIP + 기반 모델 라이선스 + 대표 로짓 + 번들 목록). 인계 결론은 네 문장이다: 후보를 고정하고 남겨 둔 12문항을 같은 조건으로 확인했다 / 형식 12/12 · 완전 일치 10/12이고 한도 초과 두 문항의 판단은 틀렸다 / 모델과 기록을 보관했고 같은 환경에서 대표 원문 · 로짓을 복원했다(차이 0) / 합성 자료의 작은 결과라서 실제 자동 승인이나 운영 품질을 입증하지 않는다.

- **향후 계획 및 다짐**
  - 올려 둔 `project_completion_ver2.ipynb`는 **셀 출력이 저장돼 있다**(Colab NVIDIA L4). 그래서 이 TIL의 8-3 · 8-4 숫자는 슬라이드와 **같은 값을 노트북 출력에서도 직접 확인**했다(🧭 4-①). 슬라이드 8장의 실행 조건도 “Colab NVIDIA L4 · BF16 · greedy 192토큰 · seed 42 · test 12 · 1회”다.

## 🧭 종합 QA 체크포인트

> 아래 교안별 내용 전체에 공통으로 적용되는 테스트·품질 관점을 먼저 모았다. 표의 **근거 교안** 번호로 🎯 상세 내용을 찾아볼 수 있다.

### 1. test를 열기 전에 · 후에 코드가 막는 것 (fail-fast 입력·환경 검사)

| 검사 | 어긋나면 | 막으려는 문제 | 근거 교안 |
|---|---|---|---|
| 패키지 2개 버전 (transformers 5.22.2 · accelerate 1.15.0) | `RuntimeError` | 다른 버전으로 실행 | 0 |
| 입력 파일 5개 존재 (7장 두 JSON + 3장 세 파일) | `FileNotFoundError` | 다른 실행의 파일 섞임 | 8-1 |
| 후보 = `full_sft` · 선정 근거는 **dev** · `test_used` False · `deployment_ready` False | `assert` | 마지막에 배운 방법으로 후보를 바꿈 · 이미 test를 본 기록 | 8-1 |
| 두 7장 기록의 모델 · revision · 세 파일 지문 · 생성 설정이 모두 같음 | `assert` | 7장 기록이 지금 파일을 가리키지 않음 | 8-1 |
| `weight_dtype` = SFT 보고서의 저장 정밀도 | `assert` | 정밀도가 다른 평가 | 8-1 |
| ZIP 경로가 복원 폴더 안 · 중복 없음 · 상위 폴더 `sft_model/` · `candidate_model`이 이미 있으면 중단 | `ValueError` · `FileExistsError` | 경로 조작 · 이전 결과 덮어쓰기 | 8-2 |
| 토크나이저 어휘 · 대화 템플릿 · EOS가 기반 모델과 같음 | `assert` | 다른 틀로 평가 | 8-2 |
| `frozen_manifest.json`이 이미 있음 | `FileExistsError` | test 결과를 본 뒤 설정을 바꿔 덮어씀 | 8-2 |
| 동결 파일 · 입력 5개 · 생성 설정 · 평가 규칙의 지문이 동결 기록과 같음 | `assert` | 동결 뒤에 무언가 바뀜 | 8-3 |
| `holdout_access.json`이 이미 있음 | `FileExistsError` | 같은 test로 후보를 다시 고름 | 8-3 |
| test 해시 · 12문항 · 고유 ID · 그룹 2개 · train · dev와 그룹이 겹치지 않음 · 대화 역할 | `assert` | 다른 test · 누수 | 8-3 |
| GPU · BF16 지원 (T4면 멈춤) | `RuntimeError` | 후보와 다른 정밀도로 평가 | 8-3 |
| 번들 ZIP 해시 = `.sha256` · 번들 안 파일 목록과 지문 · 동결 기록 ↔ 최종 보고서 ↔ 모델 파일 지문 | `assert` | 보관 중 변경 · 짝이 안 맞는 번들 | 8-4 |
| 같은 환경이면 복원 원문 · 로짓이 **정확히** 같음 | `assert` | 복원 오류 | 8-4 |

- 게임 QA로 바꾸면: **최종 회귀(블라인드 검증)를 돌리기 전에 빌드 번호 · 테스트 계획 · 합격 기준을 잠그고, 한 번 돌린 뒤에는 같은 시험지로 후보를 다시 고르지 않는 것**과 같다.

### 3. 세 층의 증거 = QA의 세 층의 판정

| 증거 | QA로 바꾸면 | 이 장에서 |
|---|---|---|
| 파일 해시 | 빌드 체크섬 (같은 빌드인가) | `file_sha256`, 포장 해시 + 내용 해시 |

- 하나가 다른 것을 대신하지 못한다. 인계할 때는 **어떤 근거가 확인됐고 무엇이 남았는지**를 나눠서 적는다.

### 4. Claude가 짚어준 확인 포인트

**① 올려 주신 노트북은 내 L4 실행의 저장된 출력이고, 슬라이드와 정확히 같다 (Claude가 출력과 파일을 대조)**
- 노트북 출력의 환경은 Python 3.13.16 · torch 2.14.1+cu130 · transformers 5.22.2 · **NVIDIA L4**다. 셀 2의 Drive 파일 목록(`candidate_manifest.json` 3,267 · `evaluation_report.json` 121,629 · `sft_report.json` 56,210 · `training_data.zip` 6,386바이트)은 올려 주신 파일의 크기와 **바이트 단위로 같다.** `candidate_manifest.json` 안의 `sft_report.json` 지문은 올려 둔 `sft_report_69f212.json`의 지문과 같고, 데이터 ZIP 지문도 같다. `sft_model.zip`(`1e969486…`)은 이번에 올리지 않았지만 6장 DPO가 기록한 지문 · 7장 평가 보고서 · 8장 노트북 출력이 모두 같은 값을 가리킨다.
- 출력의 숫자가 슬라이드와 같다: 형식 12/12 · status 12/12 · 참조 완전 일치 10/12, 동결 지문 `ab60580799…`, 설정 지문 `7c7c93e5…`, 번들 지문 `80c79500…`(17개 · 0.932GiB), 복원 로짓 차이 0.0. 슬라이드의 8장 실행 조건이 L4이기 때문에 3~6장 때처럼 “교안은 5060, 내 환경은 L4라 비슷하지만 다르다”가 아니라 **지문까지 같다.** 같은 입력 · 같은 환경이면 지문까지 재현된다는 8장의 주장이 내 실행에서 확인된 셈이다.

**② 내 7장 실행은 API 부분까지 끝났다 — 11/25 TIL의 표현을 바로잡는다 (Claude가 `evaluation_report.json` 확인)**
- 11/25 TIL에서 7-3을 “실행 전”이라고 적은 것은 그때 올린 노트북에 출력이 없었기 때문이다. 이번에 올려 주신 `evaluation_report.json`에는 **API 호출 2건**이 남아 있다: 가온팀 80,000원 질문 → 검색 `policy01-v2` · 형식 통과 · 200인데 “한도 이하이므로 승인 불필요”(**업무 판단 오류**, 80,000 > 75,000), 통신비 질문 → 검색 빈 목록 · abstained · 200(맞음). 교안과 같은 결과다.
- `source_response_matches`는 `true`(복원한 SFT의 dev 한 문항 원문이 이전과 같음), `reviewed_examples`의 상태는 `reviewed_same_text`, `test_used`는 `false`로 기록돼 있다. 즉 8장 입력 검사의 “test 미사용” 조건도 내 파일에서 통과한다.

**③ dev의 약점이 test에서도 같은 유형으로 재현됐다 — 우연이 아니라는 신호 (Claude 해석)**
- 7장 dev에서 모범답안과 달랐던 건 초과 금액 문항이었고, 8장 test에서도 틀린 두 문항이 over_limit이다(교안 3장 SFT 결과에서 dev의 오답 두 개도 over_limit). 그래서 “형식은 배웠고 금액 비교 판단은 아직 못 배웠다”가 새 그룹에서도 확인됐다. 다만 2그룹 · 12문항의 합성 자료라서 일반 성능으로 넓히지 않고, 7장 4강이 제안한 **금액 비교는 코드로 계산하는 선택지**를 다음 수정 방향으로 남긴다.

**④ 포장 해시와 내용 해시를 둘 다 남기는 이유 (노트북 설명 + Claude 연결)**
- 노트북 문구: 압축 파일의 포장 방식이 달라도 모델 내부 바이트는 같을 수 있어서 모델 폴더의 파일별 해시도 남긴다. 2장 TIL에서 “ZIP은 다시 만들면 해시가 달라질 수 있다(확인 필요)”고 적어 둔 우려와 이어지는 설계로 읽힌다(포장이 다른 ZIP 두 개를 직접 비교해 본 건 아니라서 확인 필요). 그리고 해시는 **신뢰할 수 있는 별도 기록과 비교**해야 하고, ZIP과 해시를 함께 바꿀 수 있는 상황의 신원 검증 수단은 아니다.

**⑤ 번들에는 이런 설계 선택이 있다 (코드 읽기)**
- **순환 방지**: `bundle_manifest.json` 자신을 해시 목록에 넣으면 순환하므로 내용 파일만 목록에 넣고, ZIP 전체의 해시는 `handoff_bundle.sha256`로 **밖에** 둔다. 복원 때는 이 외부 해시를 먼저 대조한다.
- **원격으로 메우지 않기**: `local_files_only=True`는 빠진 파일을 원격에서 새로 받아 메우지 않아서 “어떤 파일로 재현했는지”가 흐려지지 않게 한다.
- **`allclose`와 구분**: 4장의 `allclose`(허용 오차)와 달리 8장은 같은 환경에서 `torch.equal`로 값이 **정확히** 같은지 본다. 다른 환경이면 `same_environment: false`로 기록하고 일치를 강제하지 않는다.
- **인증 없는 요청 경고**: 출력에 `HF_TOKEN` 시크릿을 못 읽었다는 경고(Colab UI에서만 시크릿을 읽을 수 있음)가 있지만, 실행은 끝까지 됐다. 토큰이 없으면 요청 한도가 낮고 다운로드가 느릴 수 있다는 뜻이다.

## 8장. 최종 검증과 모델 인계

### 8-1 : 용도와 한계 — 모델의 용도와 한계 정리하기
- **핵심 개념**:
  - 흐름: 용도와 확인 범위 정하기 → 어떤 모델을 이어 쓰는지 찾기 → 7장 기록과 실제 파일 연결 → 근거와 주장 구분.
  - **용도를 좁혀야 결과를 읽을 수 있다**:

    | 구분 | 이번에 확인한 범위 | 확인하지 않은 범위 |
    |---|---|---|
    | 자료 | 가상 부서 12개의 합성 출장 규정 | 실제 회사 규정의 변화와 다양한 표현 |
    | 입력 | 질문 + 관련 근거를 **직접 제공** | 검색된 근거의 품질 |
    | 행동 | 금액 비교 · 승인 시점 · 근거 부족 보류 | 예약 실행 · 경비 승인 권한 |
    | 결과 | 형식 검사 · 원문 관찰 · 산출물 복원 | 운영 안정성 · 업무 전체 정확도 |

    - 코드에 적힌 용도: **합성 출장 규정으로 파인튜닝 결과와 재현 조건을 설명하는 수업용 예제**. 사용 범위 밖: 실제 출장비 자동 승인 · 새로운 회사 규정의 정확성 보장 · 운영 서비스 배포 승인.
  - **마지막에 배운 방법이 후보는 아니다**: 3장 SFT · 4장 LoRA · 5장 QLoRA · 6장 DPO 중 후보는 7장에서 dev로 고른 **full_sft**(형식 12/12 · 복원 · API 연결 확인)이고, 남은 실패는 70,000원 > 65,000원인데 “승인 불필요”라고 답한 것이다.
  - **7장 기록이 지금 파일을 가리키는지 확인**한다(`check_candidate_inputs`): 후보 = full_sft · 선택은 dev · test 미사용 · 모델 · revision · 세 파일 지문 · 생성 설정 · 정밀도. 하나라도 다르면 멈춘다. 교안 출력: “후보: full_sft”, dev 선택 이유와 알려진 실패 두 개, 이번 모델의 용도. 이 셀에서는 `training_data.zip`의 어떤 문항도 읽지 않는다.

- **QA 체크포인트**:
  - **범위를 먼저 적는다** — “무엇을 확인했나”와 “무엇을 확인하지 않았나”를 같은 표에 둔다. 테스트 리포트의 **테스트 범위 / 범위 밖** 항목과 같다.
  - **선택 이유와 알려진 실패를 한 묶음으로** — 후보를 정한 근거(dev)와 남은 결함을 같이 가져간다.

### 8-2 : 재실행 조건 고정 — 모델과 재실행 조건 고정하기
- **핵심 개념**:
  - 흐름: 재실행 조건 구분 → ZIP과 내부 모델 파일 확인 → JSON 설정 해시 → 평가 기준까지 동결 기록에 저장.
  - **seed만으로 같은 실행이 되지 않는다** — 층마다 기록할 값이 다르다:

    | 층 | 기록할 값 | 영향 |
    |---|---|---|
    | 모델 | 전체 commit · 내부 모델 파일 SHA-256 | 어떤 가중치를 실행했나 |
    | 입력 | 데이터 ZIP · messages와 문서 · chat template | 모델이 실제로 읽는 토큰 |
    | 생성 | `max_new_tokens` · `do_sample` · `repetition_penalty` · EOS | 출력 선택과 종료 규칙 |
    | 수치 실행 | dtype · torch · CUDA · GPU · 라이브러리 | 연산 경로와 반올림 |

    - 이번 값: `do_sample=False` · `max_new_tokens=192` · `repetition_penalty=1.1` · seed 42 · `torch.bfloat16` · NVIDIA L4 · torch 2.14.1+cu130 · transformers 5.22.2. seed 하나가 같아도 모든 장치와 라이브러리에서 **비트 단위 결과가 보장되지는 않는다**(노트북 문구).
  - **포장 해시와 내용 해시를 둘 다 남긴다**: `sft_model.zip`은 통째의 지문(`1e969486…`), `model_files`는 안의 6개 파일(`chat_template.jinja` · `config.json` · `generation_config.json` · `model.safetensors` · `tokenizer.json` · `tokenizer_config.json`) 각각의 지문이다. 토크나이저 어휘 · 대화 템플릿 · EOS가 기반 모델과 같은지도 `assert`한다. 기반 모델의 원본 라이선스(Apache-2.0)도 `BASE_MODEL_LICENSE.txt`로 번들에 보관한다. 해시는 **“같은 바이트”만 알려 준다.** 파일과 해시를 함께 바꾸면 못 잡고, 서명이나 출처 인증이 아니다.
  - **설정 해시: 순서는 무시, 값은 반영** — `json.dumps(..., sort_keys=True, separators=(",", ":"))`로 직렬화한 뒤 해시한다. 키 순서 · 들여쓰기 · 공백은 같은 지문이고, `max_new_tokens` 192 → 96은 다른 지문이다(교안 출력 세 줄 모두 True). 서로 다른 직렬화 규칙 사이의 동등성은 자동으로 보장하지 않는다.
  - **무엇을 성공으로 셀지도 먼저 정한다** (`evaluation_rules`):

    | 지표 | 묻는 것 | 못 보는 것 |
    |---|---|---|
    | `format_ok` | 출력 계약을 지켰나 | 금액 비교 · 판단 |
    | `status_match` | 답함 / 보류가 맞나 (형식 통과 응답에서만) | 승인 필요 여부 |
    | `reference_exact` | 참조와 글자까지 같나 | 다른 표현의 맞는 답 |

    - 사람이 읽을 기준도 같이 적는다(`human_reading`): 금액 비교와 한도 경계 · 예약 전 서면 승인 여부 · 현재 제시된 규정 · 근거 부족과 지원 불가의 구분 · 인용의 관련성. 자동 필드와 문자열 일치는 전체 의미 평가를 대신하지 않고, 2개 그룹의 결과를 운영 정확도로 일반화하지 않는다는 한계도 규칙에 적는다.
  - **test를 열기 전에 동결 기록을 남긴다**: 후보 · revision · 입력 지문 5개 · 모델 파일 지문 · 정밀도 · 생성 설정 · 생성 설정 지문 · seed · 대화 틀 지문 · 평가 규칙과 지문 · 비교 모델(baseline, full_sft) · 복원 표본 선택 규칙(`over_limit` 중 데이터 순서의 첫 번째) · 분모 12 · 그룹 2 · 환경을 `frozen_manifest.json`에 적는다. 교안 출력: “test 개봉 전 동결 완료: True”, 동결 기록 지문 `ab60580799…`, 설정 지문 `7c7c93e5…`. 동결은 **결과를 보기 전에 규칙을 적어 두는 것**이고, 시험지를 본 뒤 채점 기준을 바꾸지 않는다.
- **QA 체크포인트**:
  - **“같은 실행”은 여러 층의 조건이다** — 모델 · 입력 · 생성 · 수치 실행을 따로 기록한다. 테스트 리포트에 빌드 번호 · 데이터 버전 · 옵션 · 기기를 모두 적는 것과 같다.
  - **합격 기준과 분모를 결과 전에 정한다** — 테스트 계획서의 합격 기준을 사전 승인받는 것과 같다.
  - **해시의 한계를 같이 적는다** — 지문은 동일성이지 진위가 아니다.

### 8-3 : 최종 평가와 복원 — 최종 평가와 모델 복원 확인하기
- **핵심 개념**:
  - 흐름: 조건 확인 후 test 개봉 → 같은 입력으로 base와 SFT 실행 → 지표와 한도 초과 원문 읽기 → 번들에서 파일과 실행 복원.
  - **test는 한 번만 연다**: ① GPU · BF16(T4면 멈춤) → ② 동결 대조(파일 · 규칙 지문) → ③ 개봉 기록(`holdout_access.json`에 개봉 시각 · 동결 기록 지문 · `test_used: True`) → ④ test 검사(12문항 · 2그룹 · train · dev와 분리). 교안 출력: 최종 평가 문항 12, 그룹 `['policy02', 'policy11']`, 복원 확인용 대표 문항 `policy02-over_limit`, test 파일 지문 `2bca42ac…`. **동결 기록(`test_opened: False`)과 개봉 기록은 다른 파일에 둔다.** 동결 파일을 고치면 지문이 바뀌어서 “언제 무엇을 정했나”가 흐려지기 때문이다.
  - **정답은 입력에 넣지 않는다**: `messages[:2]`(system · user)만 모델에 넣고 모범답안(`expected`)은 채점용으로만 보관한다. 남기는 값: 고치지 않은 원문 · 새 토큰 수 · 정상 종료 여부 · 192토큰에서 잘렸는지 · 지표 6개. 같은 것: 문항 12개 · 질문과 근거 · 토크나이저 · 대화 틀 · 생성 설정 · seed · BF16 · GPU. 다른 것: **가중치**(학습 전 Qwen vs 3장 SFT). 모델 두 개를 동시에 올리지 않고 하나가 끝나면 `del` · `empty_cache` 후 다음 모델을 올린다.
  - **결과: 형식 12/12, 완전 일치 10/12** (총평의 표). 그룹별 full_sft 완전 일치는 policy02 5/6 · policy11 5/6이고 틀린 문항은 둘 다 over_limit이다. 그룹별 결과를 같이 남기는 이유는 일부 조건의 실패가 평균에 가려지지 않게 하려는 것이다. 조건: Colab NVIDIA L4 · BF16 · greedy 192토큰 · seed 42 · test 12 · 1회.
  - **base 0/12는 “형식 계약”의 0이다**:

    | base 원문 모양 | 개수 | 예 |
    |---|---|---|
    | ```` ```json ```` 코드 펜스로 감쌈 | 9 | policy02-below 등 |
    | `answered` 한 단어 | 2 | policy02-missing · policy11-missing |
    | 설명문, 192토큰에서 잘림 | 1 | policy11-boundary |

    - 펜스로 감싼 원문 예(나래팀): `"citations": []`로 인용이 비어 있고 규정 문장을 그대로 베꼈다. SFT가 바꾼 것은 같은 입력에서 **펜스 없는 JSON 한 줄**, 근거가 없으면 abstained다.
  - **status는 맞는데 승인 판단은 반대다**:

    | 문항 | 답 | 핵심 문장 |
    |---|---|---|
    | policy02-over_limit | SFT | 질문의 1박 80,000원은 **한도 이하**이므로 사전 승인이 필요하지 않습니다. |
    | | 참조 | 질문의 1박 80,000원은 한도를 **초과**하므로 예약 전 서면 승인을 받아야 합니다. |
    | policy11-over_limit | SFT | 질문의 1박 115,000원은 **한도 이하**이므로 사전 승인이 필요하지 않습니다. |
    | | 참조 | 질문의 1박 115,000원은 한도를 **초과**하므로 예약 전 서면 승인을 받아야 합니다. |

    - 두 문항 모두 `format_ok` True · `status_match` True · `reference_exact` False이고 **업무 판단은 틀렸다.**
  - **번들만으로 파일과 계산을 되살린다**: ① ZIP 해시를 `.sha256`과 대조 → ② 번들 안 파일 목록과 지문 → ③ 모델 로드(`local_files_only=True`) → ④ 원문 · 로짓 비교. 교안 출력(복원 기록): `file_hashes_match` true · `same_environment` true · `raw_response_matches` true · `logits_exact` true · `max_abs_logit_difference` 0.0.

    | 확인 | 알려 주는 것 |
    |---|---|
    | `file_hashes_match` | 같은 파일 |
    | `logits_exact` | 같은 계산 (이 환경) |
    | `raw_response_matches` | 같은 출력 |
    | (모두 해당 없음) | **업무 정답** |

    - 다른 GPU · 다른 버전에서 모든 토큰이 같다는 보장은 아니고, `same_environment`로 기록한다.
- **QA 체크포인트**:
  - **test는 한 번만, 개봉을 기록으로 남긴다** — 같은 test로 후보나 설정을 다시 고르면 test가 dev가 된다(2장의 원칙이 여기서 코드로 강제된다).
  - **실패한 문항의 원문을 읽는다** — status가 맞아도 판단은 반대일 수 있다. 숫자(형식 · status)만 보면 놓친다.
  - **0의 종류를 구분한다** — base의 0/12는 업무 오답이 아니라 형식 계약의 0이다.
  - **그룹별로도 센다** — 평균이 일부 그룹의 실패를 가리지 않게 한다.

### 8-4 : 근거와 인계 — 근거를 남겨 모델 인계하기
- **핵심 개념**:
  - 흐름: 주장과 근거 연결 → 모델 카드에 용도 · 실패 · 재현 조건 → 추론 모델과 보고서를 번들로 → 인계 범위와 다음 수정 조건.
  - **주장마다 근거와 조건을 붙인다**:

    | 설명할 주장 | 실제 근거 | 같이 적을 조건 |
    |---|---|---|
    | SFT가 JSON 형식을 지켰다 | test 형식 12/12와 원문 | 합성 2그룹 · greedy 192 · 패널티 1.1 |
    | 한도 초과 판단은 아직 틀린다 | 두 over_limit의 금액과 답 | 80,000 > 75,000 · 115,000 > 110,000 |
    | 보관 모델을 다시 실행했다 | 파일 해시 · 대표 원문 · 로짓 차이 0 | 같은 L4 환경 · 대표 입력 1개 |
    | 운영 배포 준비가 안 됐다 | 업무 오답 · 작은 합성 자료 | 인계와 사용 승인은 별개 |

    - `decision.reason`: 합성 2그룹의 최종 관찰이며, dev에서 확인한 업무 판단 실패가 있고 운영 적합성을 입증하지 않았다.
  - **모델 카드(`MODEL_CARD.md`): 용도 · 출처 · 결과 · 한계** — 절: 용도와 범위 / 출처와 학습 / dev 선정 근거와 알려진 실패 / 동결 뒤 최종 평가 / 실행과 보관. 문구: test 그룹 policy02 · policy11은 각 6문항이며 **12개의 독립적인 업무 표본으로 볼 수 없고**, 분모는 모델별 전체 12문항이며, status 일치는 형식 통과 응답에서만 인정했고, 참조 완전 일치는 answer 문자열과 citations 순서까지 같다는 뜻이며 의미 정답률이 아니다. 제시된 근거를 직접 입력했으므로 **검색 서비스 품질은 측정하지 않았고**, test 결과를 보고 후보나 설정을 다시 고르지 않았다. 첫머리에 “운영 배포 준비: false. API 연결과 파일 복원은 업무 판단의 정확성을 보장하지 않습니다.”가 있다.
  - **인계 번들: 17개 파일, 약 0.93GiB**:

    | 파일 | 들어 있는 것 | 언제 |
    |---|---|---|
    | 8장 코드 ZIP · `project_completion.ipynb` | 코드 | 수업 시작 |
    | `handoff_bundle.zip` | 모델 · 기록 · 보고서 · 카드 | 보관 · 복원 |
    | `handoff_bundle.sha256` | 번들 전체 지문 | 복원 전 대조 |
    | `restoration_report.json` | 이번 복원 결과 · 환경 | 복원 후 따로 |

    - 번들 안: `model/` 6개 · `frozen_manifest` · `holdout_access` · `final_report` · `MODEL_CARD` · `candidate_manifest` · `evaluation_report` · `sft_report` · `training_data.zip` · `BASE_MODEL_LICENSE` · `probe_logits.pt` · `bundle_manifest`. 교안 출력: 파일 수 17 · 0.932GiB · 번들 지문 `80c79500…`. **추론용 모델**이라서 optimizer · scheduler 상태는 없다. **Colab은 보관소가 아니다.** 번들 · 해시 · 복원 보고서를 PC나 Drive에 보관한다.
  - **인계 결론은 네 문장**(총평의 네 번째 통찰). `decision: candidate = full_sft · deployment_ready = False`.
  - **보강(교안 밖, 별도 노트북)**: 번들을 Drive에 보관하고 해시를 대조한 뒤(복사 5개 파일, `drive.flush_and_unmount()`로 올라갈 때까지 기다림), 원하면 HF 비공개 저장소(무료, 모델 카드 = README)나 Endpoint(유료, 시연 후 삭제)로 올린다. 스위치 `RUN_UPLOAD` · `RUN_ENDPOINT`는 기본 False, 토큰은 Colab 보안 비밀 `HF_TOKEN`(Fine-grained 최소 권한)이다.
- **QA 체크포인트**:
  - **주장 · 근거 · 조건을 한 줄로 쓴다** — “형식을 지켰다”가 아니라 “test 형식 12/12(합성 2그룹, greedy 192)”로 쓴다. 테스트 리포트의 **결론 / 근거 / 환경** 세 칸과 같다.
  - **인계 ≠ 사용 승인** — 모델을 넘겨도 `deployment_ready`는 False이고, 알려진 실패와 사용 범위 밖을 모델 카드에 같이 적는다. 게임 QA의 **알려진 이슈 목록을 빌드와 함께 넘기는 것**과 같다.
  - **보관은 짝으로** — 번들과 외부 해시, 복원 보고서를 함께 보관한다. 해시가 없으면 복원 전에 같은 파일인지 확인할 수 없다.
